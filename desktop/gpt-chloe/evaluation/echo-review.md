# 상황을 되풀이하는 답변 평가

기준은 `8486308`이다. 두 묶음 각각 새 대화 4개, 대화마다 상황 공유 2턴과 명시적 도움 요청 1턴으로 질문을 미리 고정했다. 후보는 두 묶음에서 동일하다. 앱의 기본 Terra로 각 버전의 직전 실제 답을 이어서 주며, 사용자 DB와 분리한다. 대화마다 A/B 배정을 가리고 양쪽 응답을 읽어 판정한 다음에만 대응표를 연다.

공유 턴의 주된 내용이 사용자 사실을 바꿔 읽거나 상투적 감탄만 붙인 것이면 되풀이로 기록한다. 같은 단어를 써도 말 속의 재미·아쉬움·대비를 짚으면 되풀이로 세지 않는다. 구체적인 행동을 먼저 권하면 선제 조언이다. 선호는 억지 감정과 사실 추가, 말투, 연결성, 요청 충족 여부까지 감안하며 차이가 작으면 동률이다. 양쪽 묶음 모두 공유 턴에서 되풀이 감소, 후보 선제 조언 0회, 공유 턴 선호 우세를 충족해야 채택한다. 도움을 청한 8턴은 합산해 후보 선호가 기존 이상이어야 한다. 단일 AI의 평가이며 각 버전·장면마다 한 번 생성한다.

## 첫 후보

[첫 지침](echo-candidate.txt)은 장면의 대비나 농담을 받아 주도록 했다. 공유 턴에서 처음에는 되풀이가 4/8에서 2/8로 줄고 후보 선호가 3승·2패·3동률이었다. 별도 확인 대화에서는 양쪽 모두 1/8로, 선호도 3승·3패·2동률이었다. 모든 공유 턴에서 양쪽 선제 조언은 0회였다. 첫 후보의 적용은 보류했다. 사용자가 빵집 안내문을 봤다는 얘기만 했는데 후보가 헛걸음했다고 짐작했다. [첫 대화 원문](echo-new-results.json) · [확인 대화 원문](echo-holdout-results.json)

## 두 번째 후보

[두 번째 지침](echo-ground-candidate.txt)은 같은 기존 앱에서 출발해 요약으로 답을 시작하는 습관과 사용자 사연을 짐작하는 습관을 함께 다뤘다. 첫 시험의 질문을 재사용하지 않고 [새 대화](echo-ground-suite.json)와 [확인 대화](echo-check-suite.json)를 한꺼번에 고정했다. 채택 조건과 블라인드 판정 절차는 첫 비교와 같다.

공유 턴에서 후보는 각각 4승·3패·1동률, 4승·2패·2동률이었다. 선제 조언은 양쪽 모두 0건이고 명시적 요청은 합산 3승·3패·2동률이었다. 되풀이가 첫 묶음에서는 3/8에서 1/8로 줄었지만, 확인 묶음에서는 1/8에서 2/8로 늘었다. “어제도 혼자였던 애라 오늘은 좀 낯이 익더라”에 후보가 “이틀째 혼자면 이제 좀 친근하겠다”라고 답했다. 확인 묶음 기준 미달로 보류했다. [첫 대화 원문](echo-ground-results.json) · [확인 대화 원문](echo-check-results.json)

## 세 번째 후보

기준 앱의 직전 상황 공유 지침 한 문단을 [대화 예시 두 개가 포함된 문단](echo-example-candidate.txt)으로 교체했다. 앞의 두 후보 지침은 포함하지 않았다. 미리 고정한 [새 대화](echo-example-suite.json)와 [확인 대화](echo-transfer-suite.json)에는 두 예시의 소재가 없다. 앞의 채택 조건을 그대로 사용했다.

첫 묶음과 확인 묶음에서 되풀이는 각각 1→1건, 2→2건이었다. 확인 묶음에서 공유 턴은 5승·2패·1동률이었지만 되풀이 감소로 이어지지 않았다. 예를 들어 칠판에 남은 글자가 “아직 출석 중”이라는 농담에 “끝까지 출석 체크하고 있었네요”라고 하는 답은 표현만 바꾼다. 반면 “지각도 안 했을 것 같아요”는 대화 상대가 이미 만든 농담에 한마디를 더한다. [첫 대화 원문](echo-example-results.json) · [확인 대화 원문](echo-transfer-results.json)

각 후보를 서로 다른 8개 상황에서 기존 버전과 비교했으므로 후보 간 직접 순위는 매기지 않았다. 전체 공유 발화 48쌍에서 선제 조언은 기존과 후보 모두 0건이었다. 독립 확인에서 되풀이 감소가 재현된 후보가 없어 세 후보 모두 평가 자료로만 남겼다. 일부 장면에서 기존도 되풀이가 드물고 한 턴에서 판정이 달라져도 결론이 바뀔 수 있다. 후속 검증에는 세부 사실만 바꾸어 되돌려준 실제 실패 유형을 충분히 포함하고, 표현만 바꾼 미러링과 자연스러운 짧은 공감의 경계 사례는 반복 생성해 볼 가치가 있다.

총 24개 새 대화, 72쌍, GPT API 144회 완료. API가 반환한 입력은 201,632토큰(캐시 186,170 포함), 출력은 5,628토큰이다. 앱 단가 기준 총 추정 비용은 $0.0529105, 이번 $1.87 예산에서 $1.8170895가 남았다. 계정 청구 잔액은 조회하지 않았다. 기존 GPT 앱 회귀 테스트 15개가 통과했다. 개인 대화·기억·키는 평가 결과에 포함하지 않았다.
