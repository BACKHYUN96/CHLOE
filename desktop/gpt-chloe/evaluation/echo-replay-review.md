# 농담과 감상에 대한 응답 반복 검증

기준은 `140d7a0`의 GPT PC 앱이다. [후보 문단](echo-replay-candidate.txt)은 PERSONA의 마지막 출력 언어 지시 직전에 추가했다. API 모델, 말투 설정, 저장된 기억이 없는 시작 상태와 [사용자 발화](echo-replay-suite.json)는 동일하다. 각 조건은 독립 DB에서 자기 실제 응답을 다음 턴에 전달한다. 시험용 합성 대화만 사용한다.

기존 앱의 이전 블라인드 판정에서 되풀이로 기록된 [식빵 첫 턴](echo-new-results.json), [종이학 첫 턴](echo-example-results.json), [칠판 둘째 턴](echo-transfer-results.json)이 포함된 대화를 통째로 재사용한다. 새 대화는 슬리퍼·요리 수첩·빗방울이며 후보 예시와 겹치지 않는다. 각 버전에서 같은 6개 대화를 3회씩 처음부터 생성한다. 각 회차·대화마다 A/B를 독립 무작위로 배정해 버전과 사용량을 숨기고, 세 회차 판정을 모두 저장한 후 대응표를 연다.

공유 턴에서 상대의 말을 동의어나 감탄으로 되돌려주는 게 주된 내용이면 되풀이로 센다. 장면을 되짚더라도 말한 대목의 재미나 여운에 새롭게 화답하면 허용한다. 요청 전 행동을 권하면 선제 조언으로 센다. 선호 판정은 과장·사실 추가·질문으로 흐름 끊기·한국어 어감까지 고려하며, 요청 턴은 결과물의 정확성과 제약 준수를 본다. 적용 조건은 기존 장면과 새 장면 각각에서 합산 되풀이 감소 및 공유 답변 선호 우세, 전체 후보 선제 조언 0건, 마지막 요청 턴에서 후보 선호가 기존 이상인 것이다. 세 반복의 수치도 따로 공개한다.

## 판정 결과

| 회차·장면 | 공유 중 되풀이 기존→후보 | 공유 선호 후보/기존/동률 | 요청 선호 후보/기존/동률 |
| --- | ---: | ---: | ---: |
| 1회 기존 장면 | 2→1 | 2/2/2 | 1/1/1 |
| 1회 새 장면 | 2→0 | 3/1/2 | 1/0/2 |
| 2회 기존 장면 | 3→3 | 2/1/3 | 1/1/1 |
| 2회 새 장면 | 1→0 | 1/3/2 | 2/0/1 |
| 3회 기존 장면 | 3→1 | 2/1/3 | 1/2/0 |
| 3회 새 장면 | 1→0 | 4/1/1 | 1/1/1 |
| 기존 장면 합계 | 8→5 | 6/4/8 | 3/4/2 |
| 새 장면 합계 | 4→0 | 8/5/5 | 4/1/4 |
| 전체 | 12→5 | 14/9/13 | 7/5/6 |

기존 장면과 새 장면의 공유 턴은 각 18쌍이다. 과거에 오류가 확인된 바로 그 발화만 추리면 9쌍에서 되풀이가 6→1건이었다. 공유 턴 전체 36쌍에서 선제 조언은 양쪽 모두 0건이었다. 상황별 합산 선호와 되풀이 감소, 요청 턴 선호 조건을 모두 충족해 후보 지침을 적용했다.

- 1회차 빗방울 경주에서 후보는 “응원하던 선수, 출발하자마자 팀전으로 전환했네.”라고 답해 사용자가 꺼낸 경기 농담을 이어 갔다. 2회차 식빵에서는 후보의 “한쪽만 햇볕 쬐고 나왔네.”가 색깔을 다시 묘사한 기존 답보다 자연스러웠다.
- 칠판에 이름 한 글자가 남았다는 첫 발화에서 후보는 세 회차 모두 일반적인 감정과 사실을 되돌려 주는 데 그쳤다. 칠판 제목을 여섯 글자 안으로 써 달라는 요청에서도 후보는 세 번 모두 공백을 빼고도 일곱 글자였다. 합산 개선에도 남은 사례다.
- 새 장면 2회차의 공유 선호는 기존 3승, 후보 1승, 동률 2건이었다. 동일한 6개 장면을 반복했고 단일 AI가 판단했다. 36쌍은 서로 다른 사용자 36명의 평가가 아니다.

버전 배정과 토큰을 숨긴 판정표 및 대응표 해제 후의 전체 응답은 회차별로 확인할 수 있다. [1회 판정](replay1-ballot.json) · [1회 원문](replay1-results.json) · [2회 판정](replay2-ballot.json) · [2회 원문](replay2-results.json) · [3회 판정](replay3-ballot.json) · [3회 원문](replay3-results.json)

## 사용량과 반영 확인

API 요청 108회 완료. 입력 156,580토큰(캐시 148,991 포함), 출력 3,760토큰이었다. API 완료 이벤트의 사용량에 앱 단가를 적용한 추정 비용은 $0.03383855다. 이번 $1.82 예산에서 $1.78616145가 남았다. 계정의 실제 결제 잔액은 조회하지 않았다. 각 회차·버전의 호출 상한은 $0.29로 총 $1.74였다.

반영한 서버 소스와 평가 후보의 파일 해시가 일치했다. 적용 후 기존 회귀 테스트 15개 통과, PC 서버 재시작 후 상태 API의 정상 응답을 확인했다.
