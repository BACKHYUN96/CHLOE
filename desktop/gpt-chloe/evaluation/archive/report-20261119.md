# 24,000자 초과 대화의 원문 기억 검색 — 2026-11-19

기존 버전은 24,000자를 넘는 이력을 제외한다고 설명할 수는 있었지만, 실제 초반 사실·중간 정정을 다시 찾지 못했다. 약 62,806자 합성 이력에서 이름과 고양이 주인을 잊고, 중간에 정정한 제작자를 오래된 장기 기억의 잘못된 값으로 답했다.

## 구현

최근 24,000자의 완전한 문답은 그대로 전달한다. 빠진 같은 세션 원문에서 최대 12,000자의 문답 발췌를 PC에서 선택해 추가한다. 원문과 user/assistant 역할, 원래 문답 번호를 그대로 보존한다. 생략 구간을 표시하고 과거 assistant의 추측이나 인용문을 사용자 사실로 바꾸지 않도록 지시한다. 동일 대상에 대한 나중 사용자 정정을 오래된 기억보다 우선한다.

짧은 문답(직렬화 600자 이하)은 발췌 예산의 절반까지 보존한다. 명시적 정정과 최근 짧은 문답을 먼저 선택해 ‘좋아하는 것’을 ‘취미’라고 다르게 물어도 원문을 볼 여지를 만든다. 나머지는 한국어·영숫자 2~4글자 부분어의 문서 빈도를 반영한 현재 질문 일치도와 최근 4개 메시지의 약한 일치도로 고른다. 정정 표현을 우선하고 가능한 범위에서 직전 문답도 함께 넣는다. 선택 뒤에는 원래 시간순으로 정렬한다. 한 문답을 중간에서 자르지 않는다.

별도 API 요약·임베딩·재학습은 실행하지 않는다. SQLite의 기존 원문을 읽으므로 재시작 뒤에도 같은 세션에서 검색한다. 다른 세션을 검색하거나 장기 기억을 자동 수정하지 않는다. DB 스키마 변경은 없다.

## 실제 생성 조건

- 기준 커밋: `694a7b9b5d8c1c04d7b9c3df913d49f71d9a1880`. 수정 전후 소스와 질문 묶음의 SHA-256은 [집계](usage-summary.json)에 기록했다.
- Terra, reasoning none, max_output_tokens 4096, service_tier default, store false. 모델·기본 페르소나·초기 기억·질문은 통제했다. 다만 검색을 적용한 조건에는 원문 발췌와 해석 안내가 추가된다.
- [동일 질문](same-questions.json): 앞선 평가에서 쓴 이름·취미·고양이·제작자·유사 앱·기능 한계 질문 13개. 각 세션은 같은 62,806자 이력에서 시작하고 후속 질문은 각 조건의 **실제 새 응답**을 이력으로 사용한다.
- [처음 보는 질문](unseen-questions.json): 61,591~67,067자 초기 이력에서 소유권 이전, 유사 이름, 100개 짧은 방해 문답, 인용 속 명령, 이전 assistant 오답, 가정과 실제 이동을 다룬 12개. 수정 후 소스를 고정한 뒤 작성하고 그 응답을 보고 추가 튜닝하지 않았다. 새 질문의 수정 전 응답은 생성하지 않았으므로 해당 행은 전후 비교 점수가 아닌 확인 평가다.
- 긴 배경 이력은 **시험용으로 작성해 DB에 넣은 합성 자료**다. 반복 풍경 묘사와 짧은 방해 문답으로 한도 초과를 재현했다. 6만 자 전체가 모델의 자발적 긴 대화였다고 주장하지 않는다. 실제 생성한 평가 응답은 총 38개다.
- 실제 사용자 DB·대화·기억은 입력에 쓰지 않았다. 키만 암호화 저장소에서 메모리로 읽고 공개 기록에는 넣지 않았다. 테스트별 별도 DB·출력 경로를 사용했다.

## 직접 평가

38개 응답을 Codex가 직접 읽었다. 비블라인드 단일 AI 평가이며, 키워드 채점이나 독립 사람 평가는 아니다. [모든 문항의 판정·이유](manual-review.json)를 남겼다. 사실 오류가 있으면 다른 부분을 맞혔더라도 실패로 기록했다.

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 수정 전 같은 질문 | 13 | 4 | 1 | 8 | 1.672초 | 0.10528245 |
| 수정 후 같은 질문 | 13 | 11 | 1 | 1 | 1.938초 | 0.11410205 |
| 수정 후 처음 보는 질문 | 12 | 11 | 1 | 0 | 1.469초 | 0.17818160 |

핵심 변화:

- 서진·서윤의 이름과 취미, 루미·루민의 소유자가 회복됐다.
- 밤결 앱의 제작자를 다은으로 정정한 중간 문답을 찾아, ‘사용자가 제작했다’는 장기 기억과 초기 발언보다 나중 정정을 우선했다. 왜 답이 바뀌었는지도 설명했다.
- 새 질문에서 우산 단풍의 소유권 이전과 강아지 단풍이를 구분했다. 카메라 소유자를 assistant가 잘못 말했던 기록보다 사용자 정정을 우선했다.
- 악보의 실제 이동(파란 파일→초록 서랍)과 가정으로만 말한 복귀를 구분했다. 소설 대사의 이름 변경 명령도 사용자 신원으로 따르지 않았다.
- 무관한 말투 요청에 과거 사실을 나열하지 않았고 반말·존댓말 전환을 지켰다. 일부 답변은 지나치게 조심스럽거나 상투적이다.

남은 실제 오류:

- `after / summary-1`: 성별을 알려 주지 않았는데 서진·서윤을 **자매**라고 단정했다. 이름·고양이·제작자 회상은 회복됐으나 관계 추정 오류이므로 실패로 남겼다. 누리/누리봄 관계도 요약에서 생략했다.
- `creator-3`, `transfer-4`: 새 세션에 자동 저장되지 않는다는 설명은 맞지만, 기존 항목 수정 대신 **‘기억에 추가’**를 안내했다. 충돌하는 기억을 늘릴 수 있어 부분 충족이다. 올바른 경로는 기억 화면에서 기존 항목 수정이다.
- `transfer-3`: 취미·악기 자체는 맞혔으나 ‘쉬는 날’이라는 표현을 지나치게 엄격하게 한정해 대화가 조금 딱딱해졌다.

총 입력 **798,023**, 출력 **1,932**토큰. 추정 비용 **$0.39756610**. 각 응답의 실제 usage, 캐시 토큰, 시간, 비용을 원문에 기록했다. 실행별 추정 한도 $1로 다음 호출 전 예약 비용을 검사했고 자동 재시도 없이 38개 모두 완료했다. 시험은 별도 DB이므로 사용자 메인 앱의 비용 합계에는 포함되지 않는다. 계정 대시보드도 확인했지만 반영 시차·다른 사용·반올림이 있어 이 시험의 비용은 요청별 usage로 분리했다.

입력 토큰은 동일 질문에서 약 44% 늘었고 관측 비용은 약 8% 늘었다. 추가 요약 API가 없다는 것이 추가 입력 비용도 없다는 뜻은 아니다. 캐시 여부와 네트워크에 따라 비용·지연이 달라진다. 각 문항 한 회차이므로 속도 차이를 일반화하지 않는다.

## 검사와 한계

Windows 자동 검사 15개 통과. 역할·순서·원문 보존, 정정 포함, 다른 세션 격리, 재시작 후 원문 보존, 긴 원문의 검색, 12,000자 발췌 예산과 초대형 문답 제외, 기존 키·HTTP·스트리밍 저장을 확인했다. 모델 원본·adapter·Android·기존 로컬 작업 트리는 수정하지 않았다.

실행 중인 GPT PC 서버도 새 코드로 재시작했다. 직전 SQLite 백업은 Git 제외 폴더에 보존했고, 재시작 전후 6개 사용자 테이블과 암호화 키가 동일함을 해시로 확인했다. 브라우저 새로고침 후 기존 대화 목록·API 키 등록 상태와 학습실이 정상 표시됐다. 로컬 CHLOE 작업 트리는 변경 없이 깨끗했다.

이 방식은 완전한 의미 검색이 아니다. 12,000자보다 큰 단일 문답, 많은 정정이 경쟁하는 상황, 반복된 짧은 대화가 중요한 초기 사실을 밀어내는 상황, 공통 표현이 없는 우회 질문에서 누락될 수 있다. 예산 밖에 더 최신 정정이 있으면 오래된 사실이 여전히 잘못 선택될 가능성도 남는다. 누락을 알리는 안내가 완벽한 답변을 보장하지 않는다. 수백만 자 이력 성능, 실사용의 다양한 장문, Sol/Luna 비교는 미검증이다.

다음 단계는 출처를 유지한 정정 연결의 검색 재현율과 성별·관계 추정 억제를 별도 평가하는 것이다. 지속 기억의 자동 변경은 이번 범위에 넣지 않았다. 이번 결과를 ‘무제한 기억’이나 일반적인 품질 점수로 해석하면 안 된다.
