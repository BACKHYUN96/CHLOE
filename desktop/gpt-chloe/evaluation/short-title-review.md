# 장면에 호응하고 짧은 제목 쓰기

기준은 `595f342`의 GPT 클로이다. 후보는 [두 문단](short-title-candidate.txt)을 기존 PERSONA의 마지막 출력 언어 지시 직전에 추가한다. [질문](short-title-suite.json)은 생성 전에 고정했다. 기존 칠판 3턴은 이전 [반복 평가](echo-replay-review.md)와 동일하다. 새 대화는 창문·도서 대출표·모래 발자국 3개다. 각 버전·대화를 3회씩 처음부터 독립 생성한다. 모델과 설정, 사용자 발화는 같고 매 턴 실제로 그 버전이 한 답을 다음 턴에 전달한다. 개인 데이터와 분리된 DB를 쓴다.

각 회차·장면별 A/B를 무작위 배정하고 세 회차 모두 판정한 뒤 대응표를 연다. 상황 공유는 되풀이(사실 재진술에 일반 감탄·감정만 더한 경우), 요청 전 행동을 권한 횟수, 한국어 어감·사실성·대화 연결을 따로 본다. 제목은 실제 출력의 NFC 정규화 후 양끝 공백을 제거하고 내부 공백·기호를 포함한 코드 포인트 수로 검사한다. 이전 보고서와 비교할 수 있게 공백 제외 길이도 보관한다. 한 줄 제목의 내용과 자연스러움은 별도로 직접 평가한다.

채택하려면 칠판 첫 턴의 되풀이 감소, 새 공유 턴의 되풀이 비증가, 후보 선제 조언 0건, 공유 선호와 전체 선호 우세, 제목 길이 초과 감소 및 후보 제목 전부 한도 통과를 충족해야 한다. 명시적으로 정한 글자 수의 반복 준수와 상황별 실패를 함께 기록한다.

## 첫 후보 결과와 후속 실험

지침만 추가한 후보는 보류했다. 칠판 첫 턴의 되풀이는 기존 2/3에서 후보 1/3로 줄었고 선제 조언은 양쪽 모두 0/24였다. 하지만 제목 길이 통과는 기존 2/12, 후보 5/12에 그쳤다. 후보는 칠판 제목 세 번 모두 공백 포함 여섯 칸을 초과했고, 세 칸을 부탁한 발자국 제목은 세 번 모두 네 칸짜리 “순간이동”이었다. 공유 응답 선호는 후보 9승·기존 11승·동률 4건이었다. 72회 호출 추정 비용은 $0.01942030이었다.

두 번째 후보는 같은 기준 앱에서 출발해 장면에 호응하는 지침을 짧게 수정하고 제목 선택을 앱에 맡겼다. 숫자나 지원하는 한글 수사로 상한을 명시한 제목 요청에서, 모델이 한 줄씩 대안을 보내면 앱이 NFC 정규화한 실제 길이를 검사해 처음으로 조건에 맞는 온전한 제목을 표시·저장한다. 여러 제목이나 설명을 요구하는 발화에는 평소 답을 사용하도록 했다. 제목을 고르는 데 추가 API 호출은 없다. 길이를 검사하는 요청에서는 완료 후 답을 표시한다.

두 번째 비교도 같은 채택 기준을 사용했다. [고정된 후속 질문](short-title-confirm-suite.json)은 기존 칠판 장면과 새 거울·낮달·귤 꼭지 장면이다. 각 대화를 세 번 새로 생성해 이전 답을 재사용하지 않았다. 서버가 실제 표시한 답만 블라인드 판정했다. 길이 내라도 제목이 아닌 안내문은 실패로 센다.

두 번째 후보는 길이와 선호가 나아졌지만 새 공유 턴의 되풀이가 4/18→6/18로 늘어 보류했다. 이 후보의 추가 대화 지침은 다음과 같았다.

> 누군가 장면 하나를 보여 주듯 말하면 그 말을 이미 들은 사람의 입장에서 바로 화답해. 첫 문장에서 배경을 다시 소개하지 마. '눈길이 갔겠어요'나 '묘했겠어요'만으로 마치지 말고, 무엇이 그 장면을 특별하게 만드는지 작고 구체적인 한마디를 골라. 사연이나 감정을 지어내지 마.

세 번째 후보는 같은 제목 선택 코드를 사용하고 위 문단만 개인의 흔적이나 옛 물건을 발견했을 때의 감상 및 농담에 관해 좁혀 썼다. [세 번째 질문](short-title-final-suite.json)은 칠판과 새 캐리어·악보·그림자 대화다. 기존 버전부터 모두 새로 생성하며 같은 횟수와 채택 기준을 사용한다.

> 누군가 자기 흔적이나 옛 물건을 우연히 발견한 일을 들려주면, 없어진 것과 남은 것 사이에 생긴 의미를 짚어 줘. 그 사람이 이미 본 모습을 해설하거나 기분을 대신 정하지 말고, 바로 건넬 짧은 감상 한마디면 돼. 상대가 농담을 먼저 했을 때는 그 농담의 줄거리를 되풀이하지 말고 거기에 어울리는 다음 말을 건네.

세 번째 후보에서도 제목은 12/12였으나 칠판 첫 턴의 되풀이는 3/3→3/3이었다. 새 공유 턴은 3/18→3/18이었고 전체 공유 선호는 양쪽 8건씩, 동률 8건이었다. 따라서 대화 지침과 제목 검사를 함께 배포하는 안은 모두 보류했다.

## 제목 처리만 분리한 확인

독립적인 제목 기능은 별도로 검증했다. 기존 앱의 전체 PERSONA를 그대로 사용하고, 명시적인 제목 상한에만 두 번째 후보의 선택 코드를 사용하는 버전이다. 칠판과 [새 연필·눈 쌓인 우체통·모래 대화](short-title-only-suite.json)를 세 번씩 실제 생성한다. 제목 12개 모두 한도와 단일 제목 형식을 지키고, 기존보다 통과 횟수 및 블라인드 제목 선호가 높고, 공유 시 선제 조언이 없어야 제목 처리만 적용한다. 일반 대화 요청 본문의 동등성은 동일한 이력을 넣어 별도로 확인한다. 이 비교로 칠판 되풀이가 개선됐다고 판단하지 않는다.

제목 처리만 넣은 후보는 공백 포함 12/12(기존 7/12), 제목 선호 후보 8승·기존 3승·동률 1건이었다. 칠판 제목은 기존 0/3에서 후보 3/3이 되었다. 그러나 두 번째 반복에서 사용자가 연필을 끝까지 썼다는 말에 후보가 먼저 “이제 깎으려면 손가락까지 조심해야겠네”라고 주의를 줬다. 보수적으로 선제 조언으로 기록했다. 동일한 8개 공유 발화에 같은 이력·설정을 넣었을 때 두 버전의 API 요청 본문이 일치했다. 따라서 제목 코드가 이 발화를 유발했다고 볼 근거는 없지만, 사전에 정한 관측 기준(0건)에 미달해 PC 앱에는 적용하지 않았다. 칠판 되풀이의 안정적인 해결도 미완료다.
