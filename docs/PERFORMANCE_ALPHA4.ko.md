# alpha4 성능 측정판

목표는 음질을 유지하며 CPU 스레드 수가 실제 합성 속도에 미치는 영향을 휴대전화에서 측정하는 것이다. 기존 4스레드 고정을 해제하고 앱이 확인한 CPU 수(최대 32) 안에서 수동 선택한다. 최대 자원 점유율이나 특정 스레드가 더 빠르다고 전제하지 않는다.

## 설치와 모델

제공 APK는 `-PperformanceEdition=true`로 빌드한 **CHLOE Voice Lab Performance**, applicationId `ai.chloe.voicelab.performance`다. 새 환경에 기존 alpha3 서명키가 없어 기존 앱을 덮어쓰지 않고 나란히 설치하도록 했다. 기존 앱과 내부 데이터는 유지된다. 새 성능판은 별도 앱 저장소를 사용하므로 모델 폴더를 한 번 가져와야 한다. 기존 앱에서 가져왔던 로컬 원본 폴더를 선택하면 되고 모델을 다시 변환할 필요는 없다. 내부 모델만 남아 있다면 [기존 모델 준비 안내](ALPHA3.ko.md)로 원본을 복원한다.

성능판은 처음에 1.7B를 선택한다. 0.6B 선택도 가능하다. 모델·화자·정밀도·seed·음성 토큰 상한은 바꾸지 않는다. GPU 가속과 스트리밍은 이번 APK에 포함하지 않았다. CPU가 실제 활성 백엔드인지 JNI에서 읽어 기록한다. 단순 GPU 빌드 옵션 존재를 실행 지원이나 속도 개선으로 간주하지 않는다.

## 사용 순서

1. 기존 CHLOE 앱에서 중지를 눌러 추론 메모리를 해제한다. 비교 중 충전 상태·절전 모드·주변 온도를 가능한 한 일정하게 유지한다.
2. 성능판을 설치하고 모델 가져오기 → 초기화. 같은 문장·말투로 비교한다. 처음에는 기본 짧은 문장이 적당하다.
3. 단일 테스트는 스레드 선택 → 합성 시작이다. 자동 재생을 켜면 기존처럼 첫 출력 타임스탬프도 기록한다.
4. **CPU 자동 비교**는 준비 1회 후 대표 스레드 수(2·4·6·8·앱이 확인한 CPU 수 중 유효·중복 제거)를 2회씩 실행한다. 두 번째 회차는 역순이다. 모델은 재사용하고 스레드만 변경한다. 준비 실행은 통계에서 제외한다.
5. 자동 비교는 WAV를 저장하지만 재생하지 않는다. 실제 첫 재생 출력은 미측정으로 두고 첫 PCM 준비·WAV 수신 시간만 기록한다. 단일 합성의 자동 재생으로 선택 후보의 실제 출력 지연을 따로 확인한다.
6. 완료 후 **성능 비교 JSON 내보내기**로 전체 측정을 공유한다. 후보 스레드로 단일 합성·재생도 확인한다. 결과를 자동으로 최적 설정에 적용하지 않는다.

일반적으로 앱이 CPU 8개를 확인하면 준비 1회 + 4개 설정 × 2회 = 9회다. 스레드 수나 문장 길이에 따라 수분 이상 걸릴 수 있다. 실행 동안 화면이 꺼지지 않게 하고 화면 이탈·중지 시 비교를 종료하며 부분 결과를 저장한다. 사용자가 중지하면 추론 프로세스를 종료하므로 재초기화가 필요하다. 열 상태가 SEVERE 이상이면 새 자동 비교를 시작하지 않으며, 실행 중 관측되면 현재 실행 결과를 저장한 뒤 다음 실행을 중단한다. Android의 클럭·전력·열 보호를 해제하지 않는다.

## 측정 정의

- 각 설정의 생성 시간 최저값·중앙값·RTF 중앙값·실제 측정 수를 표시한다. 반복 2회는 진단용으로 지속 성능이나 통계적 확신을 보장하지 않는다. 순서·온도·클럭 변화가 포함된다.
- RTF는 생성 시간 ÷ 출력 길이다. 출력 길이가 달라지면 화면에 표시하므로 발음과 단어 누락·추가를 확인한다. 길이가 같아도 음질 확인은 필요하다.
- worker PSS와 native heap은 기존처럼 1초마다 관측한다. 최고 PSS와 최고 열 상태는 관측 최대치이며 연속적인 절대 peak가 아니다.
- 각 생성의 시작·끝 배터리 온도, 전압, 충전 연결 상태, 배터리 수준, 순간 전류(µA), charge counter(µAh), 절전 모드, 시스템 가용 RAM과 low-memory 상태를 기록한다. 미지원 속성은 null일 수 있다. 전류 부호·갱신 주기는 기기 구현에 따르며 단기 실행에서 charge counter가 변하지 않을 수 있다.
- worker 프로세스 CPU 시간(ms)도 기록한다. 기기 전체 CPU/GPU 사용률이나 앱만의 정밀 에너지 측정값이 아니다. RAM을 불필요하게 할당하거나 배터리를 소모하는 작업을 추가하지 않는다.
- 비교 JSON은 상태(completed/stopped/error/thermal_limit 등), 입력·모델·정밀도·seed, 각 회차의 스레드와 준비 여부, 순서, 생성·첫 PCM·WAV 지연, 텔레메트리와 요약을 담는다. audio_id는 내부 WAV/개별 JSON과 연결된다.
- 입력 문장과 기존 기기 식별 정보도 보고서에 포함된다. 사용자의 파일 선택 내보내기 외에 외부 전송은 없고 INTERNET 권한도 추가하지 않는다.

## 빌드

```sh
./gradlew -PperformanceEdition=true :app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:assembleDebugAndroidTest
```

JDK 17, Android SDK 35, Build Tools 35.0.0, NDK 28.2.13676358, CMake 3.22.1을 사용한다. Windows는 `gradlew.bat`를 사용한다. 생성 APK 경로는 `app/build/outputs/apk/debug/app-debug.apk`다. `performanceEdition` 없이 빌드하면 원래 applicationId를 사용하므로 기존 설치본의 서명과 호환되는 키가 있어야 업데이트할 수 있다.

## 아직 검증할 항목

S26 Ultra 실제 생성 시간, 최적 스레드 수, 반복 성능, 음질·열·배터리 변화는 폰에서 측정해야 한다. 현재 앱은 음성 전체를 생성한 뒤 재생하므로 스트리밍의 잠재적 첫 출력 지연까지 측정하지 않는다. GPU/NPU 백엔드, Android 성능 힌트와 sustained-performance mode, 코어 고정·클럭 강제 설정은 구현하지 않았다. GPU는 별도 호환성·출력 정확성·속도 검증 후 도입 여부를 결정한다.

## 실제 빌드 검증

ARM64 Debug APK 빌드, 단위 테스트 16개, lint(오류 0·경고 11), Android 기기 테스트 APK 빌드에 성공했다. lint 경고는 의존성 버전·ChromeOS ABI·KTX 제안이다. 패키지명·앱 표시명·버전·서명 검증과 ARM64 전용 라이브러리, 모델 미포함, INTERNET 권한 없음, native Release -O3, 모든 native ELF와 ZIP의 16KiB 정렬을 확인했다. [빌드 기록](validation/performance-alpha4/build.json)에 파일 크기·SHA-256·서명 인증서 해시를 기록했다.

연결된 Android 기기가 없어 기기 테스트 APK를 실행하지 않았고 실제 성능은 미측정이다. 모델과 녹음, 서명키는 소스 ZIP이나 Git에 넣지 않는다.
