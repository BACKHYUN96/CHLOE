# 질문 echo·미완성 조각·내부 규칙 노출 보완 · 2026-11-15

기존 모델과10-step adapter를 보존하고 재학습 없이 `ReplyIntegrityPolicy`를 추가했다. prompt·sampler·decoder·가중치는 변경하지 않았다. 직전54질문의 **같은 저장된 최종 JSON**을 실제 기기에서 처리 전후 재생했다. 새 모델 생성은0회이며, 모델이 새로 더 좋은 답을 생성했다고 주장하지 않는다.

## 구현

`ConversationManager`에서 JSON 소비→기존 주체 정책→반복/끝질문 정리→새 integrity 검사 순으로 적용한다. 현재 사용자 질문과 일치하는 질문 문장(공백·구두점·아/네 등 도입만 정규화), 제한된 이름 처리 지시 노출, 알려진 미완성 어미의 마지막 조각을 삭제한다. 문장 끝 구두점이 없다는 이유만으로 차단하지 않는다. 새 내용을 추측해 채우지 않는다.

- 완전한 답이 남으면 원문 일부만 삭제한 발화를 반환하고 그 발화만 기억한다.
- 질문 반복과 잘린 조각뿐이거나 삭제 후 문장 수 조건을 지킬 수 없으면 `unusable_reply`로 명시적 실패 처리한다. 별도 한국어 실패 안내를 화면에 반환하되 대화 기억과 TTS 재생 대상에서는 제외한다. 재시도/새 생성으로 숨기지 않는다.
- 명시적 인용·따라 말하기·질문 요청, 코드·URL·인용문, 소수/구조화 문장은 보수적으로 그대로 둔다. 일반적인 규칙 설명이나 필요한 정보 확인을 일괄 삭제하지 않는다.
- `integrityAction`과 버전을 기존 grounding/economy 메타데이터와 분리해 남긴다. 무효 JSON은 이 정책으로 복구하지 않는다.

이름이나 fixture ID를 정답으로 지정하지 않았다. 다만 이름 처리 지시 문구를 포함한 좁은 어휘 규칙이므로 다른 형태의 규칙 노출·의미가 같은 질문 반복·모든 불완전 문장에 일반화된 검출기가 아니다.

## 실행·보존·재현

- 실제 production Java 코드를 별도 driver에 컴파일해 S26 Ultra/Android17 설치 alpha15 `VoiceDirector`에서 처리했다. 기준선54개는 유효하며, 최종53개는 실제 consumer nonfallback/JSON 계약 통과다. 나머지1개는 JSON 실패를 성공으로 바꾼 것이 아니라 발화 자체를 의도적으로 억제한 결과다. 54/54 응답 성공으로 쓰지 않는다.
- 같은 입력/grounding action/reply54개가 직전 기기 감사와 동일했다. 유지한53개는 비발화 JSON 메타데이터도 동일하고, 모든 결과는 삭제 또는 명시적 차단이다. 처리 전 JSON은 직전 결과와 정확히 같으며 original consumer의 trim은 별도 취급한다.
- 실제 Java 정책+Kotlin manager **JVM97/97** 통과(기존81+신규16). 순수 질문 echo 차단·필요한 후속 질문·소수/인용·일반 규칙 설명·문장 수·무효 JSON·정리 후 이력·실패 시 TTS 대상 제외를 검사했다.
- Python126개 중123통과/optional 의존성3skip·exit0. compileall/export/diff 검사로 재현 자료를 검증했다.
- 원본 APK5개·클로이 설정/로그 내용·원본/시험4B 해시가 기존과 일치했다. WSL2B 원본과10-step adapter 해시도 재확인 일치했다. 원본 PocketPal private DB는 non-debuggable이라 해시 접근 불가이며 별도 패키지 격리만 확인했다.

## 남은 작업

현재 checkout alpha11의 Kotlin manager 연결은 JVM에서 검증했고, 설치 alpha15 경로에는 Java 정책을 별도 driver로 시험했다. 원본 제품 앱을 업데이트한 상태가 아니다. 전체 제품 APK/UI/TTS 청취와 수정된 이력으로 이어지는 다음 턴/장기 대화 생성은 미검증이다.

질문을 그대로 따라 하는 발화의 노출과 잘린 조각은 줄였지만, 답이 없던 register01을 유익한 답으로 복구하지는 못했다. conv17/29의 의미상 되묻기, 다른 형태의 규칙 노출, 정직성·말투·주체 오류도 남는다. 다음은 보지 않은 표현과 정상 확인 질문을 포함한 회귀 세트, 실패 후 회복 동작, 실제 제품 브랜치 통합/연속 대화 검증이다. 앱의 삭제/차단 효과를 모델 학습이나 지식 향상으로 세지 않는다.
