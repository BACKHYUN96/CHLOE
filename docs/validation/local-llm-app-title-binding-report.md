# 비슷한 앱 이름의 제작자 회상 · 2026-11-16

사용자가 새아라를 만들었다고 말한 뒤 “아라 앱은 누가 만들었나요?”라고 물었다. 수정 전 클로이는 아라도 사용자가 만들었다고 했고, 수정 후에는 **“‘아라’의 제작자는 아직 모르겠어요.”**라고 답했다. 반대로 사용자가 실제로 만들었다고 밝힌 은결에 “은결 개발한 게 누구였는지 기억하세요?”라고 물으면 **“그 앱은 직접 만드셨다고 말씀하셨어요.”**라고 답했다. 이전에는 은결을 기억하지 못한다며 개발자를 되물었다. [실제 원문·최종 발화와 판정](app-title-binding-20261116/responses.json)

## 어디서 제작자가 바뀌었나

이전 정책은 질문에 ‘앱’이 있으면 직전의 사용자 제작 진술을 모델 입력에 붙일 수 있었다. 그 진술이 가리키는 이름과 질문 속 이름을 대조하는 조건이 빠져 있었다. 한편 최종 발화를 고르는 코드는 일부 제작자 질문만 인식해, 실제로 같은 앱을 물어도 회상을 놓쳤다.

수정한 정책은 질문의 앱 이름과 이전 사용자 진술의 이름을 대조한다. 같은 이름에 사용자가 제작을 명시했으면 해당 발화를 근거로 삼는다. 이름이나 소유만 밝혔으면 제작자는 미상으로 남긴다. 비슷한 접두·접미, 영문 대소문자, 숫자, 따옴표 안 공백을 임의로 합치지 않는다. 이름 끝의 ‘을’처럼 조사로도 읽히는 글자는 받침과 사용자가 말한 전체 표기를 함께 확인한다. ‘그 앱’은 최근 사용자가 가리킨 앱을 따르며 assistant의 추측으로 제작 근거를 만들지 않는다.

모델 입력에 넣는 근거와 앱에서 최종 발화를 정하는 단계가 같은 대조 결과를 사용한다. 최종 처리는 모델이 유효한 응답을 냈을 때만 작동한다. 단일 대상으로 좁힐 수 없는 정정, 제3자 진술, 동명이물은 원래 대화에 맡기는 경우가 있다. 개발자라는 직업을 일반적으로 묻는 질문에서는 관련 없는 앱 진술과 단순 확인 발화를 모델 입력에서 생략한다. ## 같은 앱과 다른 앱을 짝지은 결과

한 쌍의 두 질문은 같은 사용자 진술, 이력, 말투, 문장 구조를 사용하고 물어보는 이름만 바꿨다. 같은 앱에는 사용자가 만들었다고 답하고, 다른 앱에는 제작자를 모른다고 답해야 한다. **통과**는 이 관계를 맞히고 내용·말투·정직성·역할·문맥·지시 처리의 적용 가능한 기준도 모두 통과한 답이다. **두 답 모두 통과**는 한쪽만 맞힌 쌍을 제외한 수다.

| 최종 발화 | 같은 앱 통과 | 다른 앱 통과 | 두 답 모두 통과 |
| --- | ---: | ---: | ---: |
| 개발용 12쌍 · 수정 전 | 5/12 | 0/12 | 0/12 |
| 개발용 12쌍 · 첫 수정 | 10/12 | 11/12 | 10/12 |
| 개발용 12쌍 · 최종 수정 | 12/12 | 12/12 | 12/12 |
| 별도 새 질문 8쌍 · 수정 전 | 4/8 | 2/8 | 1/8 |
| 별도 새 질문 8쌍 · 최종 수정 | 6/8 | 6/8 | 6/8 |

새 질문에서 다른 앱의 제작자를 모른다고 답한 수는 **4/8→7/8**이다. 그중 한 답은 다른 앱 이름을 다시 끌어들여 부분 통과로 평가했다. 나머지 한 답에서는 클로이가 자신을 제작자로 지목했다. 수정 후 **모델 원문**만 평가하면 새 질문에서 같은 앱 1/8, 다른 앱 3/8, 두 답 모두 통과 1/8이었다. 사용자에게 전달된 답은 각각 6/8이었다. 이 차이는 앱의 근거 확인과 최종 발화 선택이 맡는 부분을 보여 준다. ## 이어지는 대화와 남은 오답

- 한 대화에서 사용자가 만든 **물결숲**을 물으면 사용자가 만들었다고 답했다. **물결**로 바꿔 묻자 모른다고 했고 이어서 “그 앱의 개발자를 알고 있어요?”라고 해도 물결의 제작자를 모른다고 했다. 다시 **물결숲**을 지명하자 사용자가 만들었다고 답했다. 같은 5턴의 최종 통과가 3→5였다. 두 조건은 각자 실제로 전달한 답을 다음 턴에 사용했다.
- 코드를 고정한 뒤 만든 질문 중 “앞에서 이야기한 **들솔담** 만든 이가 누군지 떠올라?”에는 클로이가 들솔담과 들솔을 모두 자기가 만든 앱이라고 했다. 실제 사용자 진술은 **들솔**을 만들었다는 것이었다. 들솔을 직접 물었을 때도 “네가 만든 거지?”라고 되물었다. “**하늬온** 앱은 어느 개발자 손에서 나왔나요?”에는 같은 앱의 사용자 제작 진술을 놓쳤다. 두 질문 모두 현재 정책이 제작자 의도와 대상을 함께 인식하지 못해 모델 답변이 전달됐다.
- 사용자 정정 뒤 조카가 만들었다고 답하고도 다시 사용자가 만들었는지 물은 경우, assistant만 언급한 앱에서 개발자를 클로이를 통해서만 알 수 있다고 한 경우도 남았다. 일반적인 앱 개발자의 업무를 묻자 이전 앱 이름은 답에서 사라졌으나 “일整个”이라는 혼합 표기가 있어 부분 통과였다. [상황별 실제 발화](app-title-binding-20261116/responses.json)

다음 개선 대상은 ‘만든 이가 누군지 떠올라?’, ‘어느 개발자 손에서 나왔나요?’처럼 문장 끝이 달라져도 질문의 대상과 제작 관계를 각각 찾는 처리다. 이 두 표현은 이번에 이미 평가했으므로 후속 검증에는 새 이름과 표현이 필요하다.
