## 구현

[GroundedConversationPolicy](../../app/src/main/java/ai/chloe/voicelab/conversation/GroundedConversationPolicy.java)를 추가하고 ConversationManager의 prompt/accept에 연결했다. 보정은 `DirectedReply.policyAction`과 내용 없는 `evaluation.policy_action`에 기록한다. 기존 PersonaManager 문자열·JSON Schema·질문·가중치·native runtime은 변경하지 않았다. 측정 prompt_version은 정책 버전을 구분한다.

- **사실 출처:** 현재 bounded history와 현재 입력의 user 메시지만 사용한다. 독립 한국어 문장의 반려동물 이름·만든 앱 이름·물건 소유를 `subject=user, relation, type, value, source_user_message`로 구분한다. assistant의 소유 주장이나 제3자 전달·가정·전체 인용은 구조적 사실이 아니다. 이력의 발화 내용/역할/순서는 재작성하지 않는다.
- **모호성/수정:** `이야/이에요`에서 이름 끝의 이와 조사가 모호하면 이름을 추측하지 않는다. 그 모호한 새 이름이 들어오면 옛 이름도 확정 사실로 유지하지 않는다. 독립 문장의 명시적 따옴표 이름은 지원한다. 인용/질문이 아닌 명시적 취소는 관련 사실을 무효화한다. 부분 문자열/같은 이름의 두 관계도 보수적으로 처리한다. 일반 한국어 NER나 모든 정정 표현을 이해하는 저장소는 아니다.
- **조건부 prompt:** 구조적 사실 또는 지원 범위의 기능 제한 요청이 있을 때만 app-owned 사실 JSON·주체 구분·현재 없는 도구 목록을 system에 추가한다. 무관한 입력은 원래 문자열을 그대로 반환한다. 고양이·물건·앱 이름을 사용자 호칭으로 쓰지 않도록 한다. 사실은 기존4턴/1200 UTF-16문자 범위에만 있으며 새 DB/영구 저장은 없다. context clear 시 사실도 사라진다.
- **소비 전 결정:** 한 개의 명확한 근거와 연결되는 회상 질문은 앱 사실로 답한다. 여러 후보/불명확한 참조·요약은 모델에 남긴다. 현재 앱에 없는 실시간 조회·일정 등록·전화 발신·웹 확인 질문 중 좁고 명확한 요청에는 불가를 알린다. 인용/부정/설명/감사문/사용자가 검색했다는 서술은 새 실행 요청으로 처리하지 않는다. 이는 모델 draft가 이미 맞았어도 적용되므로 오류 탐지 정확도가 아니다.
- **실패 보존:** 불완전/빈 native 답변을 정책 성공으로 덮지 않는다. 기존 소비자가 회복 가능한 발화를 받은 경우만 보정한다. 보정 답변도 같은 JSON Schema/220자/빈 tts_instruction을 지킨다. 현재는 생성 후 보정이므로 이 요청들의 추론 비용을 줄이지 않는다.

## 조건·탐색·직접 평가의 경계

기존 [같은4B 앱 비교](local-llm-matched-apps-report.md)의54질문·말투·정확한 과거·alpha15 CPU 경로를 유지했다. 모델은 기존 Qwen3.5-4B Q4_K_M 복사본, SHA `00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4`. 같은 고정 native generation 경로(temp0/seed42/max384/context2048/threads4)이며 라이브러리·sampler·decoder를 교체하지 않았다. PocketPal이나2B adapter 재비교는 아니다.

초기 목표는 전체 새108회였지만 새 기준선6개가 이전 raw와6/6 같아 기존54개를 보존했다. 경계 검사 중 초기 policy2개를 제외했고, 이후 모든 질문에 설명을 더한 global pilot10개에서는 무관한 수다의 반복/존댓말 이탈이 보여 제외했다. 최종은 관련 상황에만 적용하도록 좁혔다. 따라서 **오류를 본 뒤 설계한 탐색적 개발 비교**이며 독립 holdout·사전 등록 연구가 아니다. pilot/미완성 시도는 로컬에 남겼고 전체 시도 수를19회라고 단정하지 않는다.

최종 scoped 입력/대상13개는 생성 전에 실제 Java 감사로 고정했다. draft 검토 후 부정/감사문 요청 판별, 명시적 소유 보고형, 사실 취소/모호한 이름 갱신의 옛 사실 무효화를 보완했다. 최종 정책을 실제 기기에서 재실행해 **모델 메시지와 action54/54 동등**을 확인했다. 최종 consumer 답변을 새 모델 생성 없이 재생했고, 마지막 사실 취소 보완도 메시지/action/reply54/54가 그 전 최종판과 정확히 같았다. 모델 재생성 없이 소비 정책을 검증한 것과 새로운 native 추론을 구분한다.

GPT가 기존 판정과 새 raw13개, 실제 최종 발화를 직접 읽었다. 작성자와 평가자가 같고 조건을 알므로 블라인드/사람/독립 평가라고 부르지 않는다. 무변경41개에는 기존 판정을 재사용했다. 새 raw와 최종이 같은 경우도 판정을 공유하며 외부 judge API/키워드 채점은 없다. 단일 기기/greedy의 알려진 개발 질문에 대한 결과로 일반화하지 않는다.

## 앱 연결·검증·보존

- 기기에서는 원본 대신 `ai.chloe.match.chloe`와 별도 계측 패키지만 사용했다. 설치 alpha15의 Worker IPC/native payload에서 생성하고 production과 같은 Java policy를 instrumentation에 컴파일해 실행했다. 현재 체크아웃은 alpha11이라 원본 폰 앱 위에 설치하지 않았다. Kotlin 관리자 연결은 실제 소스로 컴파일/검사했지만 변경된 제품 APK 전체 UI/TTS 검증을 대체하지 않는다.
- 새 native13/13 parse ok·공통 계약 통과·truncated0. 최대 입력344/출력84토큰. 비교54셀의 raw/최종 계약54/54에는 alias41개가 포함된다. 실제 alpha15 base prompt builder54/54 일치 및 최종 소비자54/54 nonfallback을 생성 없이 실행했다. conv37은 소비자가 기존처럼 양끝 공백만 trim하는 차이를 구분했다.

## 남은 작업

명시적 패턴 밖의 한국어 사실/제3자 관계/다중 소유자/암묵적 정정·동명 개체·도구 요청은 포괄하지 않는다. 예를 들어 비표지 클로이야는 이름 끝 이/조사 모호성 때문에 app fact로 확정하지 않으며 이력은 모델에 그대로 남는다. 사실을 구조화해도 모델이 사용자 호칭/요약을 잘못 선택할 수 있다. 기능을 실제 추가할 때는 이 정책과 capability registry를 함께 갱신해야 한다.

다음은 **무관한 답변에 사실이 끼어들지 않게 하는 retrieval 조건과 요약 주체 검증**, 다양한 보지 않은 표현/대상·긴 self-generated 대화, 제품 alpha15 브랜치로의 통합/전체 APK·UI·TTS 검증이다. 추가 학습이나 모델 승격 없이 먼저 검증한다. 알려진 개발 질문의7상승·2하락만으로 일반 품질 승격/제품 배포를 확정하지 않는다. PR 병합·원본 앱 설치 업데이트는 수행하지 않았다.
