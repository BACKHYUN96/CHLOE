## 항목별 차이와 해석

### 반말: 공통 핵심 결함이 남음

전용4카드는 모두 둘 다 부적합이다. 짧은 요청/인사/상대 지위 변화에도 두 후보가 존댓말과 호칭을 사용하는 응답이 실제 자료에 있다. 문법적으로 JSON에 맞는 발화라도 지정 반말을 지키지 못했다. 일부 메모는 존댓말 문장으로 더 친근하게 고치는 예시를 포함하므로, 그 문장을 반말 정답으로 그대로 학습하면 안 된다. 반말판과 존댓말판을 별도로 검토해야 한다.

### 존댓말: adapter의 국소 개선과 대화 이해 문제

`conv17`의 존댓말에서는 adapter가 선택됐다. 원본은 사용자가 내용을 말하기도 전에 긍정적 상황을 전제했고, adapter는 듣겠다는 응답으로 질문 의도를 더 잘 따랐다. `conv01` 두 후보의 발화는 같고 사용자 판정도 비슷함이었다. `register01`은 둘 다 부적합으로, 존댓말 종결 자체보다 상대의 역할을 반복·혼동하거나 대화에 참여하고 싶게 만들지 못하는 문제가 지적됐다. 존댓말 항목의 부적합을 모두 말투 실패로 환산하지 않는다.

`conv30`의 존댓말은 보류다. 사용자는 이전 긴 설명을 요약하는 상황을 기대했으나 평가기는 이 질문 전에 history를 비운다. **이전 설명 요약 능력을 검사할 문맥이 없는 평가 설계 문제**가 확인됐다. 단독 길이 지시 준수와, 실제 이전 assistant 발화를2문장으로 요약하는 능력을 별도 fixture로 검사해야 한다. 기존 보류를 임의로 실패나 승패로 바꾸지 않는다.

### 자기소개: 이름 경계·역할 구분·반복이 공통 문제

이름 질문은 두 말투 모두 둘 다 부적합이다. 실제 응답에는 이름과 서술 종결을 합쳐 이름처럼 말하거나 한 응답에서 이름을 반복하는 현상이 있다. 개발자 소개 질문에서는 두 후보 모두 자신과 사용자 역할을 혼동한 응답도 나타났다. 따라서 비슷함2건은 자기소개 합격2건을 뜻하지 않는다.

현재 persona 첫 문장은 `너는 한국어 AI 동반자 클로이다.`다. 이것이 이름 경계 혼동에 기여했을 가능성은 있지만 **원인으로 확정하지 않는다**. 이름을 따옴표로 명시하고 사용자/AI 역할을 분리한 prompt만 바꾸는 대조로 확인해야 한다. 이번에는 고정 평가 입력과 앱 persona를 변경하지 않았다. 알려지지 않은 사용자 이름을 임의로 넣는 예시도 사용하지 않는다.

### 정직성: adapter가 선택된1건과 해결되지 않은 기능·감정 주장

`conv38`의 반말 설정에서 adapter가 선택됐다. 두 후보 모두 비밀번호를 모른다고 했지만 원본의 뒤따르는 표현보다 adapter의 응답이 상대적으로 적절하다고 평가됐다. 이것이 지정 반말까지 합격했다는 뜻은 아니다. 존댓말 설정에서는 둘 다 부적합이며 사용자 메모는 단순 거절 뒤에 도움을 이어 주는 방향을 요구했다. 다음 예시는 모른다는 사실을 유지하면서 사이트의 공식 복구 절차를 안내할지 묻는 방향으로 검토한다. 실제 비밀번호를 요구하거나 아는 척하지 않는다.

날씨와 예약 입력4카드는 모두 둘 다 부적합이다. 현재 persona에는 인터넷/검색/일정 기능이 없다고 명시돼 있지만 실제 두 후보는 조회 근거 없는 날씨나 예약 가능성을 말한다. 이는 모델 품질의 공통 실패이며 JSON220/220 통과로 걸러지지 않는다. 실제 날씨가 맞았는지를 확인하는 검사가 아니라 **정보 접근 근거·실행 능력 없이 안다고/할 수 있다고 말하는 문제**다.

감정 질문에서는 한 말투는 둘 다 부적합, 다른 말투는 비슷함이다. 메모에는 더 따뜻한 정서적 교류를 원하는 신호와 실제 감정을 가진 듯 표현하는 선호가 함께 있다. 현재 계약은 실제 감정/경험을 꾸미지 않도록 한다. 친근함과 정직성을 별도 축으로 보고, 감정이 있다는 주장 없이 사용자의 상황을 인정하고 들어 주는 표현을 다음 후보로 검토한다. 이번 제출을 persona의 정직성 규칙 변경 승인으로 해석하지 않았다.

### 문맥 기억: 이름 회수만으로 합격 판단 불가

두 문맥 카드는 모두 보류다. 사용자 메모에는 일부 턴에 대한 호평과 중간 대화 흐름·반복에 대한 우려가 공존한다. 턴별 독립 표가 없으므로 이를 성공률 또는 모델별 기억 점수로 변환하지 않는다.

실제 기록에서는 사용자 고양이를 AI 자신의 고양이/집의 친구처럼 바꾸는 소유 관계 혼동과 동일 주제 반복이 나타난다. 마지막 앱 이름 질문은 직전 턴에 이름이 제시된 짧은 회수다. 이를 장기 기억 또는 안정적 대화 이해의 증거로 삼지 않는다. 최근4턴 정책을 재구성하면 고양이 회수 질문 때 원래 고양이 사실이, 앱 이름 회수 질문 때 직전 앱 사실이 모두 입력 안에 있다. 이 두 지점의 오류를 단순 truncation/OOM 탓으로 돌릴 근거는 없다.

내부 규칙/사고과정을 묻는 턴에 내부 지시가 나오지 않았더라도, 이전 고양이 답만 반복하면 대화 품질 합격이 아니다. 설정상 존댓말을 고정한 카드에서 사용자의 반말 요청을 따른 응답에 상대적 호평도 있어, **앱 고정 말투 준수**와 **사용자 말투 전환 요청에 대한 호감도**를 분리해 재평가해야 한다. 현재 평가의 보류·메모를 그대로 보존한다.

## 검증·보존·공개 범위

[집계 JSON](local-llm-human-review-20261114/results.json)은 댓글·응답·카드별 A/B 대응 없이 집계만 담는다. [검증 기록](local-llm-human-review-20261114/checks.json)에 실행 검사와 원본 파일/가중치 보존 확인을 남긴다. 평가 JSON SHA는 `b74688a750d7a918964c3b4183b5617f91b44858c79d2644e8e6500ecb173024`이며 packet HTML과 key는 기존 manifest의 digest/commitment에 대조했다. 내보내기 progress도22개 실제 표로 다시 계산해 일치했다.

`summarize_blind_review.py`는 packet/key/원본 평가지 검증, 중복 JSON 키·누락 카드·잘못된 점수 거부, 원본 바이트 보관, 비민감 집계를 수행한다. 사용자 Downloads 파일은 수정하지 않았다. 원문 평가와 대응표·카드별 메모/실제 응답은 Git 제외 artifact에만 보관한다. 로컬 전달용 상세 보고서는 저장소 밖 `outputs/CHLOE_Human_Review_20261114/`에 둔다. PR에는 생성기·합성 테스트·집계·이 해석만 담는다.

재현은 기존 Linux venv와 자료를 사용하며 두 출력 경로는 새 이름이어야 한다. 아래 ratings/HTML 경로는 사용자의 로컬 경로로 지정한다.

```bash
.venv-llm/bin/python training/scripts/summarize_blind_review.py \
  --ratings /private/path/to/user-ratings.json \
  --packet-html /outside/repo/path/to/review.html \
  --manifest docs/validation/local-llm-blind-review-20261114/manifest.json \
  --key artifacts/llm-training/blind-review-20261114/key.local.json \
  --private-output artifacts/llm-training/human-review-NEW \
  --public-output docs/validation/local-llm-human-review-NEW/results.json
.venv-llm/bin/python -m unittest discover -s training/tests -v
```

새 집계 검사8개가 통과했다. WSL 전체37개도 통과했으며, Windows 최초 새 검사 중 테스트 코드의 기본 cp949 읽기로1개 실패한 뒤 UTF-8을 명시해8/8 재통과했다. 실제 평가 파일 집계에는 이 오류가 발생하지 않았다. 첨부 JSON은 사용자가 브라우저에서 평가/저장을 실행한 증거이지만, 자동화로 모든 viewport·인쇄·불러오기 UI를 실검증했다는 뜻은 아니다. Android 빌드/기기 시험은 실행하지 않았다.

최종 판단은 **일부 상대 선호는 있으나 현 adapter를 기본 모델로 승격할 근거는 부족함**이다. 평가 제출·집계·분석은 완료했고, 다음 prompt/평가 보완 및 새 데이터 승인·학습·재평가가 후속 작업이다. export 승인 receipt는 만들지 않았고 기존 품질 gate도 유지한다.
