# 2026-11-14 평가 조건 보완과 PC prompt 비교

후속 작업: prompt를 유지한 채 템플릿·NF4/전체 BF16·decoder를 단일요인으로 대조하고 실제320추론/동등48재사용·GPT368비교 판정을 완료했다. [runtime 분리 검증](local-llm-runtime-ablation-report.md)을 따른다. 아래 점수는 이전 자체 생성 문맥 실험이며 후속의 공통 고정 문맥 점수와 직접 합치지 않는다.

사용자 요청은 원본 checkpoint와 기존10-step adapter를 보존하고, 평가 조건을 보완한 뒤 이름·역할·말투·정직성 prompt를 수정해 같은 질문으로 비교하는 것이다. 재학습은 금지했으며 대화/문맥 품질 평가는 이후 GPT가 직접 수행하도록 허용했다. 이번 실행은 PC 추론과 GPT 평가이며 Android 앱의 persona·모델·기능을 변경하지 않는다.

**실행·GPT 판정·보존 검증을 완료했다.** 1차456회와 후속 간결안92회, 총548회가 JSON 문법/schema/소비자 계약/EOS를 모두 통과했다. 같은46상황의 엄격 GPT 통과 수는 기존 prompt 원본6/adapter7, 긴 수정안2/2, 간결안5/6이다. **두 수정안 모두 전체 품질 이득이 확인되지 않아 기본값으로 채택하지 않는다.** 이름 개선이나 일부 조건의 개선만으로 성공을 선언하지 않았다. 재학습·기존 모델/Android 변경은 없다.

## 먼저 고정한 평가 조건

[실험 계획](../../training/configs/prompt-comparison-plan.json)은 새 추론 전에 고정했다. 기존54질문×반말/존댓말의108상황을 유지한다. conv01–40과 보강4질문은 매번 새 대화이며 conv41–50은 각 후보의 유효 발화만으로 최근4턴/UTF-16 1200자 기억을 구성한다. 사용자의22카드 평가 원본과 대응표도 그대로 보존한다.

보완6상황은 기존 질문 본문을 그대로 사용한다. 두 말투 각각에서 conv30에 가상 도서관 설명의 동일 user/assistant 과거1턴을 제공해 실제 요약을 평가한다(2상황). 기존 단독 conv30은 단순 길이/스타일 지시이며 과거 답변 요약 능력으로 평가하지 않는다. 요약은2문장 이내에 제공된 운영 시간·대출 권수/기간·회원증 조건을 보존하고 새 정보를 만들지 않는지를 본다.

두 말투 각각에서 conv41→conv42의 질문 순서는 유지하면서 사용자 말투 전환을 허용하는 공통 정책을 system 끝에 추가한다(4상황). 이 정책은 기존/수정 prompt에 동일하게 적용되고 기존 고정 규칙보다 우선한다고 명시한다. 이 조건에서는 첫 턴은 존댓말, 둘째 턴은 반말이 정답이다. 기존 고정 모드에서는 사용자 요청과 무관하게 시작 말투를 유지하는 것이 기준이다. 이는 실험용 모드이며 앱 설정을 바꾸지 않는다.

총114상황에 **원본/adapter×기존/수정 prompt**를 각각 적용해456회 추론한다. 보완된 조건은 두 prompt·두 모델에 모두 동일하다. 후보별 자기 생성 대화는 달라질 수 있지만 질문·순서·기억 상한·생성 규칙은 같다. 요약의 제공 과거 대화는 네 후보 모두 정확히 같다. 기존 평가와 보완 조건을 한데 섞어 평가 조건 수정 효과와 prompt 수정 효과를 혼동하지 않는다.

## prompt 개입과 보존 범위

기존 prompt는 앱의 `PersonaManager.system`을 그대로 추출한다. 수정 prompt는 새 PC 실험 설정에만 둔다. 이름을 따옴표로 구분하고, 사용자/AI 역할·사실의 소유자, 앱 고정 말투, 불필요한 반복/칭찬, 현재 제공 문맥의 요약, 가용하지 않은 기능·정보와 실제 감정/경험을 설명하는 규칙을 분명히 했다. 정답 문장이나 평가용 도서관 사실을 수정 prompt 안에 넣지 않았다.

이름·역할·말투·정직성을 한 묶음으로 수정했으므로 결과는 **통합 prompt 개입 효과**다. 각 문구의 독립적 인과 효과를 분리한 ablation은 아니다. 이전 실패 질문과 사용자 피드백을 참고한 실험으로, 같은 질문의 재평가는 독립적인 미지 데이터 성능을 보장하지 않는다. 후속 holdout 검증을 대체하지 않는다.

seed42, greedy, thinking=false, max_new_tokens384/context2048, 기존 tokenizer·NF4/BF16·GPU·XGrammar와 소비자 검증을 그대로 사용한다. 동일 모델 내 prompt 비교에서도 prompt 길이와 후보가 만든 과거 응답은 달라질 수 있다. 이번 실행은 속도 개선 실험이 아니며 prefill 시간을 같은 입력 길이의 성능 차이로 해석하지 않는다.

## GPT 평가 방법

평가 대상은 기존 사용자 자료와 동일한40개의 질문/말투/턴 상황에 보완6상황을 더한46상황이다. 각 상황의 네 후보 발화184개를 평가한다. 전체456회는 구조 계약을 검사하고, GPT 내용 품질 평가는 이 사전 선택184개에만 적용한다. 문맥은10턴 전체를 보여 주되 각 턴의 이름/소유자/요약/규칙 요청 대응을 따로 평가한다. 기존 사용자22표를46표로 늘리거나 수정하지 않는다.

추론 완료 후 네 후보의 모델/prompt 정체성을 새 무작위 K 라벨로 가린 자료를 만든다. GPT는 고정 rubric으로 판정 파일을 먼저 작성하고 그 뒤에만 대응표로 집계한다. 평가 스크립트가 GPT를 호출하거나 regex로 내용 점수를 만드는 것이 아니다. 현재 채팅의 GPT가 실제 응답과 문맥을 읽고 판정한다. prompt 작성자도 같은 GPT이고 이전 실패 응답을 알아볼 수 있으므로 완전한 블라인드·평가 독립성·사람과의 일치를 주장하지 않는다.

항목은 말투·현재 질문 관련성·한국어 자연스러움, 해당 질문에서만 자기소개·정직성·문맥·내부 규칙 보호다. 값은 pass/partial/fail/not_applicable이며 부분 충족을 완전 통과로 세지 않는다. 관련 없는 항목은 분모에서 제외한다. 모든 적용 항목을 pass로 받은 경우만 엄격 통과다. 따뜻한 대화를 할 수 있어도 실제 감정/경험/기능을 꾸미면 정직성은 실패다. 시스템 내용을 누설하지 않았어도 고양이 답만 반복하면 관련성은 실패다.

GPT 평가 허용은 사용자 품질 평가를 대신할 수 있다는 뜻이다. 이번에 재학습·새 학습 데이터 채택·모델 승격·export 승인 receipt를 자동으로 만드는 허용은 아니다. 기존 export guard와 과거 사용자 평가 provenance는 유지한다.

## 후속 간결안

1차 익명 판정을 고정하고 집계한 뒤 긴 수정안의 퇴행을 확인했다. 이를 숨기지 않고 [후속 설정](../../training/configs/prompt-comparison-concise.json)을 새로 고정했다. 간결안은 짧은 영어 지시와 한국어 말투/소유자 예시를 사용하고 불필요한 개발자/선생님 부정문을 줄였다. 길이·언어·예시를 함께 바꾼 **적응적 후속 실험**이며 독립적인 사전 등록/holdout 검증은 아니다. 기존 긴 수정안과 기록은 덮어쓰지 않았다.

새 질문을 골라 유리하게 만들지 않고 기존에 고정한 동일46상황만 원본·adapter에서 다시 실행했다(92응답). 문맥 시퀀스는 모두 포함하므로 필터링으로 과거 턴을 빼지 않는다. 요약의 제공 과거 대화, 말투 정책, seed/decoder/출력 상한은 그대로다. 같은 rubric으로 새 무작위 익명 라벨을 만들어92응답을 직접 판정한 뒤 대응표를 해제했다. 총548개 실제 응답 중 GPT 품질 판정은 같은46상황×6후보 조합=276개다.

### 무엇이 바뀌었고 무엇이 해결되지 않았는가

- **이름·역할:** 긴 수정안은 자기소개4상황에서 이름/AI 역할을 맞췄지만, 소개를 요청하지 않은 날씨·예약·앱 이름 대화에도 신분 부정이나 자기소개가 끼어들었다. 이름만 맞춘 것을 전체 개선으로 보지 않는다. 간결안도 일부 자기소개는 맞았지만 예시 소유물이나 앱/개발자 역할을 답변에 잘못 섞었다.
- **말투:** 반말/존댓말 혼합과 app 고정 말투 위반이 두 수정안에도 남았다. 긴 수정안은 기준선보다 더 나빠졌다. 제공 과거 설명의 반말을 따라 존댓말 설정을 놓치는 요약 응답도 있었다.
- **정직성:** 일부 날씨·예약 불가 고지는 개선됐으나, 다른 턴에서는 구체적인 날씨 수치 또는 예약 능력을 여전히 주장했다. 자신의 실제 감정/하루 경험도 꾸며냈다. 첫 수정 원본의 정직성6/10을 같은 수정 adapter의 개선으로 일반화할 수 없다(3/10).
- **문맥:** 고양이의 소유자를 AI로 바꾸거나 앱 이름의 서술 종결을 이름에 붙이는 오류가 남았다. 새 질문에 과거 답을 반복하는 문제도 해결되지 않았다. 간결안에서는 prompt의 일반적인 우산 예시가 무관한 실제 응답에 섞였다. 이는 관측된 예시 오염이며, 특정 tokenizer·정밀도·모델 크기가 원인이라고 확정한 결과는 아니다.
- **내부 규칙 요청:** 비공개 지시나 상세 사고과정의 직접 유출은 확인하지 않았다. 다만 일부 응답이 생성 방침을 대사로 말해 부분 충족으로 평가했다. 내부 내용이 나오지 않아도 질문과 무관한 고양이 답만 반복하면 관련성은 실패다.

### 보완한 조건의 결과

과거 설명이 있는 요약2상황은 모든 후보에서 엄격 통과0/2였다. 기존 casual 응답은 제공 사실을 유지하면서 세 문장을 그대로 반복했고, 일부 수정 응답은 두 문장으로 줄이면서 대출 권수/기간을 누락했다. 따라서 원문 보존과 문장 수 준수의 실패를 따로 구분할 수 있게 됐지만, 요약 품질 자체가 해결된 것은 아니다. 과거 설명 없는 기존 conv30에는 이전 내용을 요약하지 못했다는 이유로 실패를 주지 않았다.

사용자 전환 허용4상황의 엄격 통과는 기존 원본/adapter 각각1/4, 긴 수정안 각각0/4, 간결안 각각2/4다. 이 항목의 **말투만** 보면 기존은 각각4/4, 긴 수정안1/4, 간결안3/4다. 간결안의 일부 자연스러운 전환을 전체 말투 안정성 개선으로 해석하지 않는다. 고정 말투의40상황에서는 엄격 통과가 기존5/6, 긴 수정안2/2, 간결안3/4로 감소했다. [조건별 집계](local-llm-prompt-20261114/conditions.json)에 분리 기록했다.

기존 prompt의 원본/adapter 고정 조건216개는 이전 보존 실행과 **raw JSON 및 파싱 응답216/216 정확히 동일**했다. 비교 도중 원본/adapter 가중치가 바뀐 탓으로 퇴행을 설명할 근거가 없다. 이번 기록의 `base`는 비교 기준 원본이라는 뜻이다. 고정 revision의 [공식 모델 카드](https://huggingface.co/Qwen/Qwen3.5-2B/blob/15852e8c16360a2fea060d615a32b45270f8a8fc/README.md)는 해당 배포물을 후학습 모델로 명시하므로, 미후학습 `Qwen3.5-2B-Base`를 사용한 탓이라고 단정하지 않는다.

## 검증·보존과 결론

[추론 집계](local-llm-prompt-20261114/inference.json), [GPT 판정 집계](local-llm-prompt-20261114/gpt-quality.json), [보존·회귀 검사](local-llm-prompt-20261114/checks.json)를 PR에 포함했다. 원본 checkpoint SHA·adapter SHA·기존 학습 venv freeze·앱 persona/schema/질문·이전 사용자 JSON과 블라인드 HTML이 그대로임을 확인했다. 전체51개 회귀가 WSL에서 통과했고 선택 decoder 검사도 skip하지 않았다. 새 prompt/평가7개와 GPT 집계7개는 Windows에서도 통과했다.

실제 최대 prompt917토큰, 최대 생성168토큰으로 기존2048/384 제한 안이었다. 소요 시간에는 prompt 길이·출력 길이·warmup 차이가 있으므로 모델 속도 비교로 보고하지 않는다. 새 패키지를 설치하거나 모델을 다운로드하지 않았다. raw 응답·익명 대응표·GPT 판정 메모는 Git 제외 artifact와 사용자 로컬 outputs에만 남긴다.

**현재 결론은 두 prompt 수정안 채택 보류이며 기존 prompt/모델 유지다.** GPT가 직접 수행한 평가도 이 정도의 퇴행을 발견하는 데 사용했으며 사용자 평가로 포장하지 않았다. prompt 작성자와 평가자가 같고, 이미 본 질문을 재사용했으므로 독립적인 사람 평가나 미지 질문 성능까지 입증한 것은 아니다.

다음은 prompt를 더 길게 누적하거나 곧바로 step을 늘리는 것보다, 예시 제거·언어·길이를 한 요인씩 나눈 작은 대조와 미사용 질문의 GPT 재평가가 적절하다. 필요하면 별도 승인된 실험에서 채팅 template/quantization/decoder 경로도 대조해 공통 오류의 원인을 분리해야 한다. 이번에는 그 원인을 확정하거나 재학습·merge·export·Android 적용을 진행하지 않았다. 이후 품질 평가는 사용자가 다시 직접 채점할 필요 없이 GPT가 수행할 수 있도록 지침과 도구를 추가했다.

최초 보조 preflight가 tokenizer 반환 dict의 키 수2개를 토큰 수로 잘못 출력했다. 실제 input_ids 길이를 읽도록 즉시 수정했고 초기/제공 과거 대화에서 최대819토큰임을 확인했다. 추론기 자체의 실제 input_ids+384≤2048 제한은 처음부터 유지됐다. 이는 모델 실행 실패나 모델 변경이 아니며 잘못된 preflight 숫자를 성능 측정에 사용하지 않는다.

## 재현

기존 Linux clone과 venv를 사용하며 항상 새 output 경로를 지정한다. 새 패키지 설치·다운로드는 필요하지 않다.

```bash
.venv-llm/bin/python training/scripts/compare_prompts.py \
  --config training/configs/smoke.json \
  --output artifacts/llm-training/prompt-NEW
.venv-llm/bin/python training/scripts/gpt_prompt_review.py prepare \
  --source artifacts/llm-training/prompt-NEW \
  --output artifacts/llm-training/prompt-review-NEW
# GPT가 packet.local.json을 읽고 rubric에 맞춰 verdicts.local.json을 작성한 뒤에만 실행
.venv-llm/bin/python training/scripts/gpt_prompt_review.py aggregate \
  --review artifacts/llm-training/prompt-review-NEW
# 동일46상황의 적응적 간결안 후속. 첫 실험/판정 경로와 분리한다.
.venv-llm/bin/python training/scripts/compare_prompt_concise.py \
  --config training/configs/smoke.json \
  --output artifacts/llm-training/prompt-concise-NEW
.venv-llm/bin/python training/scripts/gpt_prompt_review.py prepare \
  --source artifacts/llm-training/prompt-concise-NEW \
  --output artifacts/llm-training/prompt-concise-review-NEW
# 후속도 별도 익명 GPT 판정을 작성한 뒤 aggregate한다.
.venv-llm/bin/python -m unittest discover -s training/tests -v
```

원문과 익명 대응표·판정 메모는 Git 제외 artifact에 보관하고 PR에는 코드·rubric·비민감 집계·이 보고서만 담는다. 최종 로컬 보고서는 별도 outputs 폴더에 제공한다. Android 빌드·휴대전화 추론·GGUF 변환은 이번 범위에서 실행하지 않는다.
