## 수정한 경로

[GroundedConversationPolicy](../../app/src/main/java/ai/chloe/voicelab/conversation/GroundedConversationPolicy.java)의 model view와 요약 결정을 개선했다. 모델·adapter·native runtime·JSON Schema·기본 PersonaManager 문구는 유지한다. 측정 prompt_version만 새 정책을 구분한다.

1. **사실이 있다는 이유만으로 다시 주입하지 않는다.** 현재 질문의 대상/이름/소유 관계, 현재 새로 제시한 사실, 요약 요청과 관련된 구조적 사실만 system에 전달한다. 원래 이력의 출처 번호를 유지하며, model view 위치와 혼동해 새 소유자를 만들지 않는다.
2. **무관한 사실+단순 확인은 모델에 보내는 사본에서 쌍으로 생략한다.** 관련 없는 독립 사용자 사실과 이어지는 중립 acknowledgement만 제거한다. 현재 질문은 그대로이고 나머지 발화의 역할/내용/순서는 유지한다. 비사실 대화·의미 있는 assistant 내용·알 수 없는 이력은 임의로 삭제하지 않는다. 원래 bounded 세션은 남아 다음 회상 때 다시 사용할 수 있다. 별도 DB/장기 기억은 추가하지 않았다.
3. **요약은 근거 범위를 먼저 확인한다.** 과거 user 발화 전부가 지원하는 명시적 사실이고 assistant가 단순 확인/감사뿐일 때만 앱이 출처 보고형 요약을 만든다. 누락된 사용자 내용·의미 있는 assistant 정보·취소/모호한 사실·220자 초과가 있으면 이 결정 경로를 쓰지 않는다. 복잡한 요약은 전체 이력을 보존한 채 user의 내/제와 assistant의 내/제를 구분하라는 지시를 주고 모델에 남긴다.
4. **이름과 제작 관계를 분리한다.** 이름 어미를 확정할 수 없어도 내가 만든/제가 만든 앱이라는 명시적 발화는 제작 주체를 사용자로 표시한다. 반대로 내 앱이라는 소유 표현만으로 제작자라고 단정하지 않는다. 취소/소유-only 갱신은 이전 제작자 hint를 무효화한다. 이름을 임의로 확정하거나 평가 이름을 하드코딩하지 않는다.

보정 동작은 기존 `policy_action`에 `grounded_fact_summary`로 구분한다. 빈/불완전 native 결과를 성공으로 덮지 않으며, 유효한 소비 경로에서만 앱 요약을 사용한다. 현재 구조는 생성 후 보정이므로 결정적 요약에서도 모델 draft를 실제 생성했다.

## 남은 범위

단순 확인이 아닌 assistant 내용, 알 수 없는 표현, 복잡한 제3자/동명 관계는 보수적으로 남긴다. 이 때문에 모든 무관한 사실이 차단된다는 보장은 없다. lexical relevance가 정확한 의미 이해를 대신하지 않으며, 복잡한 요약의 모델 주체 오류와 생성 반복도 남는다. 앱 제작자 명시와 이름 어미 분리를 했어도 이름과 사용자 호칭의 혼동49는 해결되지 않았다.

다음은 반복·불필요한 질문과 이름 echo의 독립 대조, 보지 않은 사실/질문·긴 자기 생성 대화, 실제 alpha15 제품 브랜치 통합과 전체 APK/UI/TTS다. 알려진 개발 질문3개 상승·1개 하락만으로 일반 품질 승격이나 출시를 확정하지 않는다. 재학습·모델 승격·원본 설치 업데이트·PR 병합은 수행하지 않았다.
