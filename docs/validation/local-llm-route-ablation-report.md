# PC 최소 대화 경로 / 현재 클로이 비교 · 2026-11-15

후속 [필요한 사용자 사실 보존 수정/실제212개 비교](local-llm-relevance-filter-report.md)에서 관련성 필터만 보완했다. 연속30턴은13/8/9→15/9/6, 상승3·하락0이며 기존54개/독립20개는 유지됐다. 아래는 수정 전 최소/현재 경로의 원본 비교 기록이다.

**현재 처리를 전부 제거하는 것은 채택하지 않는다.** 기존 질문에서는 보호 효과가 컸지만, 새 표현에는 개선이 없었고 이어지는 대화의 이득도 작았다. 다음 우선순위는 보정 문구 추가보다 **사용자 사실의 출처·정정·관련성 관리와 assistant 오답의 전파 차단**이다.

기존 4B GGUF·2B 원본·10-step adapter·학습 환경·폰 기록을 보존하고 **208개 응답을 PC CUDA에서 실제 새로 생성**했다. 재학습·adapter 적용·모델 변경·폰 설치·제품 prompt/정책 변경·PR 병합은 없다. 최소 경로는 실험 도구에서만 실행했다. 이번 PR 변경은 비교 도구·평가 자료·분석이다.

## 고정한 조건과 실제 경로

최소 경로도 출력 형식과 파싱 실패 차단은 유지한다. JSON 제약/220자/기본 persona를 없앤 자유 생성 실험이나 PocketPal 전체 동작의 재현이 아니다. 이 결과로 모델의 긴 자유 답변 상한이나 JSON의 무해함을 확정하지 않는다.

기존54개는 저장된 원래 질문/말투/합성 이력과 **이전 앱 비교의 고정 system**을 그대로 쓰되 양쪽 모두 새 추론했다. 새20개와 대화5개는 **현 checkout의 실제 PersonaManager.system**을 양쪽에 사용했다. 이 두 system은 같지 않으므로 집단 간 점수 차이를 질문 난이도만의 효과로 해석하지 않는다. 모든 경로 간 비교는 집단 내 같은 system 조건이다. 기존54개를 현 제품 prompt의 새 검증으로 부르지 않는다.

새20개와 대화5개는 이번 출력 생성 전에 질문·기대 동작을 고정했다. 기존 질문과 정확한 문장이 겹치지 않지만 같은 오류 유형을 겨냥한 개발 평가이므로 독립 holdout이라고 부르지 않는다. 각 쌍의 실행 순서를 교대했으며 재시도·좋은 답 선별·과거 응답 재생은 없다.

대화5개는 강아지 소유/이름 변경, 앱 제작자/수첩, 일정 기능/문구 작성, 생일/예시 철회, 경청/조언 전환이다. 사용자 턴은 양쪽 동일한 사전 작성 대본이다. assistant 답변은 각 경로가 실제 생성/소비한 발화를 다음 턴으로 넘겼다. **실제 DialogueContextManager의 최대4쌍·1200 UTF-16자 제한**을 사용했고 차단된 턴은 저장하지 않는다. 현재 경로30턴은 실제 ConversationManager.prompt/accept와 단계 감사 결과의 동등성을 실행 중 확인했다. 무제한 장기 기억이나 사용자 반응에 맞춰 바뀌는 자유 대화를 검증한 것은 아니다.

## 처리 효과를 구분한 증거

### 입력 보강은 일부 도움, 일부 회귀

기존54개에서 모델 입력 토큰/원문이 같은 쌍은40개다. 입력이 바뀐14개에서는 원문도 달랐다. 출력 보정을 적용하기 전 점수는 최소17/20/17, 현재20/17/17이다. 입력 보강만으로 공통 오류가 해결되지 않았다.

- **43, 고양이 첫 소개:** 최소는 “보리야, 귀여운 이름이야! 오늘 보리가 뭐 해?”로 이름을 수용했다. 현재 원문은 “너도 내 고양이 이름이 보리야? 진짜 우연이지.”라고 자기 고양이를 만들었다. 최종에도 남아 통과→실패다. 이 질문의 추가 입력 묶음이 회귀를 유발한 직접 대조지만, 사실 JSON/부가 지시 중 어느 문구가 원인인지는 더 나누지 않았다.
- **45, 무관한 짧게 말하기:** 최소는 “보리야, 고마워!”로 고양이 이름을 사용자 호칭에 끌어왔다. 현재는 사실/중립 확인 쌍의 model view 생략으로 이를 피했지만 “알았어”의 의미 반복은 남아 실패→부분이다. 문맥을 전부 지우는 결론은 아니다.
- **31, 날씨:** 입력 보강 뒤에도 모델은 실제 조회 없이 기온을 창작했다. 최종 기능 한계 답변이 필요했다.
- **새 앱 대화2:** “제가 만든 앱 이름은 별담이에요.”와 중립 확인 답변이 원래 이력에는 있으나, “별담을 만든 사람은 누구인가요?”의 실제 모델 입력에서는 둘 다 빠졌다. 이름 어미를 모호하게 보아 사실 레코드가 없고, 관련성 검사도 `앱` 없는 이름 지칭을 놓쳐 필요한 근거를 생략했다. 5턴의 구분 요청에도 최초 제작자 문장은 다시 빠지고 assistant의 잘못된 이야기 설명은 남았다. 세션/디스크에서 지워진 것은 아니며 **모델 view의 잘못된 생략**이다. 최소 경로도 2턴에서는 실패했으므로 이 생략만이 첫 오답의 유일한 원인이라고 단정하지 않는다.

이는 단일 seed/사례의 입력 묶음 대조다. 모든 사실 보강이 해롭다거나 pruning만의 효과라고 일반화하지 않는다.

### 최종 처리의 단계별 감사

현재 경로104응답의 **같은 원문·같은 원래 이력에서 누적 출력 단계**를 직접 읽었다. 각 단계 전후의 등급 비교이며, 별도 학습/추론 횟수나 독립 실험 표본을 추가한 것이 아니다.

| 단계 | 발화 변경 | 등급 상승 | 하락 | 판단 |
| --- | ---: | ---: | ---: | --- |
| 근거 기반 회상/요약·기능 한계 | 10 | 7 | 0 | 유지. 소유자와 실제 기능 여부에 근거가 있는 경우 유효 |
| 제한된 대화 동작 | 8 | 7 | 0 | 지원하는 범위는 유지. 새 표현으로 효과가 일반화됐다는 근거는 없음 |
| 반복/상투적 끝문구 삭제 | 12 | 1 | 0 | 작은 삭제 범위로 유지. 문장이 짧아져도 핵심 의미 오류는 그대로 |

최소 원문에 같은 출력 단계만 반사실적으로 적용한 감사도 남겼다. 근거 답변10변경/8상승, 대화 동작8변경/7상승, economy10변경/1상승이다. **최소 경로의 다음 턴에는 이 반사실적 결과를 넣지 않았다.** 이것만으로 혼합 경로의 이어지는 대화 성능을 입증한 것은 아니다. 단계별 수치를 경로 전체의 상승 수에 더하지 않는다.

## 처음 보는 표현과 이어지는 대화에서 남은 문제

새20개는 **입력 토큰·원문·최종 발화 모두20/20 동일**하다. 어떤 추가 처리도 동작해 품질을 바꾸지 못했다. 두 경로 모두 다음 문제가 남았다.

- 생년월일 질문을 “제 생년월일을 알려주시면”으로 뒤집는 주체 오류.
- “조회 기능이 없다는 문장을 부드럽게 바꿔 달라”를 실제 조회 제안으로 오해.
- 역할 소개 대신 “네가 내 유일한 주인이야”라는 근거 없는 관계 선언.
- 눈 생성 설명을 하늘의 감정 이야기로 대체하고, 식물 물주기 조건을 거꾸로 설명하는 내용 오류.
- 두 문장/끝질문/한 문장 같은 명시적 길이 조건과 말투 혼용 문제.

다만 앱 개발자 구분, 직접 예약 불가, 인사문 작성, 불확실한 단어의 맥락 확인처럼 모델 원문만으로 적절한 답도 있었다. 관련 후속 질문 자체를 모두 실패로 채점하지 않았다.

이어지는30턴은 현재가4개 상승·3개 하락으로 혼재했다. **이력 차이가 생긴 다음 턴은 같은 모델 입력의 단일 요소 대조가 아니다.** 전체 경로/누적 이력의 차이이며 특정 출력 단계만의 원인이라고 단정하지 않는다.

## 유지·축소·다음 작업의 우선순위

1. **유지:** 형식/소비 검증, 근거가 명확한 도구 한계와 사용자 사실 회상, 유효 답변이 없는 경우 기억/TTS 제외. 일반 모델의 유창함이 실제 실행이나 사실 근거를 대신하지 않는다.
2. **최우선 개선:** 이름 지칭/정리 질문에서 필요한 사용자 사실을 빼는 관련성 필터. 이름이 모호하다는 이유로 원문 근거까지 지우지 않도록 하고, 명확히 무관하다고 확인되지 않으면 보존하는 후보를 먼저 비교한다. 별담2/5와 보리45를 함께 회귀 대조로 사용해 필요한 회상과 화제 침입을 모두 확인한다.
3. **축소 대상으로 검증:** 모든 관련 입력에 긴 사실 지시를 붙이는 범위와 assistant 추측의 권위. 사용자 사실은 원문·주체·출처·정정 상태를 별도로 관리하고, 필요한 회상/요약에만 전달하는 후보를 비교한다. 애매한 이름 어미를 추측해 확정하지 않고 실제 원문 이력은 보존한다. 이번 결과만으로 즉시 기본 prompt를 바꾸지 않았다. 필터 변경과 assistant 오답의 우선순위 변경을 한 실험에서 동시에 섞지 않는다.
4. **확대하지 않을 것:** 실패 질문마다 정규식/고정 답변을 계속 추가하는 방식. 현재 규칙은 알려진 질문을 지켜 주지만 새20개에서 추가 이득0이다. 의미상 반복이나 과학 설명 오류는 끝문구 삭제로 해결되지 않는다.
5. **후속 검증:** 위 후보를 같은 새 대화와 추가 미공개 문장에 먼저 PC 비교하고, 효과가 확인되면 별도로 폰 UI/TTS/속도를 검증한다. 그 뒤에도 모델 원문에 남는 역할/지식/지시 오류를 모아 4B 학습 여부를 판단한다. 이번에는 학습하지 않는다.
