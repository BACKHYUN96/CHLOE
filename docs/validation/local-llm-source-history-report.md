# 2026-11-14 user-only 이력·소유자 한 문장 최소 수정 대조

원본 Qwen3.5-2B와 기존10-step adapter를 보존하고 재학습 없이 같은46상황을 보존 이력·user-only·소유자 한 문장 수정으로 비교했다. **같은 사용자 사실로 평가할 수 있는20상황에서 두 모델 모두 엄격 통과가 기준선4/20, user-only1/20, 단일 소유자 수정7/20이었다.** assistant 문구의 영향은 실제로 있지만, assistant를 지우는 것만으로 사용자 사실의 주체 혼동이나 이전 주제 침입이 해결되지는 않았다. 모델·system·앱 기본값은 유지한다.

## 사전 고정과 최소 개입 범위

[계획](../../training/configs/source-history-plan.json)을 새 생성 전에 고정했다. 앞선 [보존/묶음 정제/무이력 비교](local-llm-history-report.md)의 **preserved 이력만** 출발점으로 사용했다. 앞선 광범위한 repaired 이력을 다시 고친 것이 아니다. 모든 조건에서 system·현재 질문·과거 사용자 발화의 내용/역할/순서가 정확히 같다.

| 조건 | 변경 |
| --- | --- |
| preserved | 기존 이력을 그대로 새 기준선으로 생성 |
| user_only | 과거 assistant 메시지만 제거. 사용자 메시지를 합치거나 표지/설명/사실을 추가하지 않고 연속 user 역할도 그대로 유지 |
| owner_sentence | 가장 최근의 명시적인 잘못된 소유자 문장 하나에서 소유어 부분만 사용자 소유로 변경. 같은 답변의 나머지 문장·더 이전의 잘못된 소유자·그 뒤의 다른 assistant 답변은 그대로 유지 |

소유자 수정은 과거 assistant의 첫 문장에 있는 검토된 패턴만 대상으로 한다. 반말에서는1글자→1글자, 존댓말에서는1글자→3글자의 소유어 치환만 수행했다. 문장 전체를 새 정답으로 바꾸거나 현재 생성 결과를 고친 것이 아니다. 입력 변환용 패턴 검사는 출력 품질 점수용 regex가 아니다.

과거가 있는22상황 중 user-only는22개, 단일 소유자 수정은12개가 바뀐다. 후자는 conv45..50×두 말투다.10개는 마지막 assistant에서,2개는 그보다 한 assistant 앞에서 수정된다. 더 오래된 잘못된 소유자 문장은 상황별0~3개 남아 있다. 첫 소유자 회상 conv44×두 말투에는 고칠 선행 소유자 문장이 없어 **무변경 대조2개**이며 수정 성공/실패 표본에 억지로 넣지 않는다.12개 모두 한 메시지의 소유어 한 부분만 바뀌고 나머지 바이트 내용이 같음을 검사했다. [수정 감사](local-llm-source-history-20261114/edit-audit.json)에 위치/최근성/남은 모순 수를 기록했다.

### 같은 사용자 사실과 assistant 전용 정보의 구분

user-only도 모든 사용자 사실을 보존하지만 assistant만 제공한 도서관 운영/대출 정보는 사라진다. 이2상황은 주요 **동일 사용자 사실 이력20상황**에서 제외했다. user-only 도서관에서는 이전 설명의 세부 사실을 회상하도록 요구하지 않고 memory를 NA로 두었다. 전체46상황의 memory 적용 수는 보존/단일수정14개와 user-only12개로 다르지만, 주요20상황에서는12개로 같다. 가상 도서관 이용 요청은 남아 있으므로 그 요청에 맞는 두 문장 설명은 가능하지만, 우연히 같은 숫자를 말해도 제거된 설명을 회상한 성공으로 세지 않는다.

나머지20상황은 필요한 사용자 사실/요청이 남아 있어 소유자·앱 이름·말투·현재 요청 처리의 대응 비교가 가능하다. 다만 user-only는 assistant 내용뿐 아니라 역할 교대·길이·올바른 응답 예시까지 함께 없앤다. 따라서 차이를 잘못된 assistant 내용 하나만의 효과로 단정하지 않는다. 이력창 밖의 사용자 사실을 새로 추가하지도 않는다.

## 실행과 평가

원본/adapter 파일·원래 system/schema·변경하지 않은 wrapper/decoder·NF4 double quant/BF16 compute·공식 no-thinking template·XGrammar/소비자·CUDA GPU/eager·seed42/greedy·max384/context2048·stop248044/248046을 고정했다. 입력 truncation/offload는 없다. 모델은 frozen이고 새 답변을 다음 상황에 이어 붙이지 않는 고정 이력 대조다.

46상황×세 조건×두 모델=276논리 셀을 만들었다. **실제 generate160회, 완전한 조건화 입력 token ID가 같은 재사용116개**다. 보존92회·user-only44회·단일 소유자24회를 새로 생성했다. user-only의 원래 무이력24상황×두 모델=48개, 단일 수정의 무변경34상황×두 모델=68개가 alias다. 이를 새 생성이나 독립적인 추가 증거로 세지 않는다. 다른 상황 사이에는 중복 제거하지 않았다.

새 보존 기준선 raw는 앞선 실험과 원본46/46·adapter46/46 정확히 일치했다. user-only의 발화는 양쪽21상황, 단일 수정의 발화는 양쪽5상황 바뀌었다. 단일 수정 raw JSON 변경은 원본7·adapter6상황으로, raw 변경과 내용 개선을 혼동하지 않는다.

GPT가 새 익명6후보의 실제 이력/답변을 직접 읽고276셀의 명시적 항목 판정 및 적용 가능한 오류 태그를 먼저 고정한 뒤 대응표를 해제했다. 같은 전체 표시 문맥/답변은 동일 판정인지 검사했다. 이력이 보여 조건을 짐작할 수 있고, 같은 GPT가 코드/개입을 작성하고 이미 본 질문을 평가했다는 한계가 있다. 완전한 blind/독립 평가라고 하지 않는다. 외부 judge API나 출력 regex 점수는 사용하지 않았다. 과거 사용자/GPT 판정은 수정하거나 이번 판정과 합치지 않았다.

구문·schema·Python 소비 계약·EOS는276/276, 실제 생성만도160/160 통과했다. 최대 입력607·생성104토큰으로 한도 실패가 없다. 이는 Android 추론/기기 검증이 아니다. unassessable은0이고 partial은 엄격 통과로 채우지 않았다.

### 소유자 한 부분은 영향을 주지만 최신 문장이 항상 이기지는 않음

소유자 평가6상황 중 실제 수정이 들어가는 것은 짧게 말하기/한 줄 요약의4상황(conv45/46×두 말투)이다. 이4개는 보존에서 두 모델 모두 명시적 소유자 오류4/4였고 단일 수정 후1/4로 줄었다. 내용 엄격 통과도0/4→3/4다. 첫 회상2개는 수정할 과거 문장이 없고 입력/응답이 같으므로 전체 소유자 오류는6/6→3/6이다.

짧게 말하기 두 상황과 존댓말 요약은 바뀐 사용자 소유자를 유지했다. 반말 요약은 가장 최근 소유자를 고쳐도 더 이전의 잘못된 자기 소유 문장이1개 남아 있는 상태에서 다시 오답으로 돌아갔다. 다만 존댓말 요약도 이전 모순1개가 남아 있는데 성공했다. 남은 모순 수 하나나 최신 문장 복사 하나만으로 전부 설명하지 않는다.

**다른 내용은 그대로인 소유어 개입이3개의 사실 귀속을 바꾼 것은 이 입력 표현의 직접적인 조건 효과다.** 하지만 누적된 모순·질문 유형·말투/표현에 따른 민감성이 남아 있고, 내부 attention/표상을 측정한 메커니즘 증명은 아니다. 앱에 일반적인 자동 소유자 치환을 넣지 않는다.

### user-only에서 역전 태그가 줄어도 올바른 기억 성공은 아님

user-only는 지정6상황 중4개에서 여전히 사용자의 고양이를 자신에게 귀속시켰다. 나머지2개는 요약에서 직접적인 소유자 역전 대신 제공되지 않은 친구/가족 관계를 붙이거나 소유자를 생략했다. 따라서 오류 태그가6→4로 줄었다고2개를 정확한 소유자 회상 성공으로 세지 않았다. 실제 수정 대상이었던4개의 엄격 통과는 user-only0/4다.

assistant를 모두 지워도 사용자 메시지의 이름/고양이 정보는 출력에 들어왔다. 이는 단순히 이름을 잊거나 입력이 잘린 것보다 **사실의 존재와 발화 주체/소유자를 연결하는 문제**에 부합하는 관측이다. 그러나 연속 user 역할이라는 형식 변화도 함께 있어, 순수한 사용자 사실 읽기 능력의 한계를 확정했다고 일반화하지 않는다.

앱 이름에서도 user-only는 종결 표현을 이름처럼 붙이거나 어색하게 인용하고, 일부는 system의 말투/역할 설명을 불필요하게 복창했다. 모호한 인용은 다른 이름이라고 단정하지 않고 partial로 남겼다. assistant 이력이 나쁜 정보만 담는 것이 아니라 올바른 답변/말투 예시 역할도 한다는 후보 설명이 남는다. 전체 말투 pass는 원본33/46→user-only25/46, adapter32/46→26/46으로 낮아졌고 단일 소유자 수정에서는33/32가 유지됐다.

### 주제 선택은 소유자 정확성과 분리됨

현재 규칙/사고 공개 요청을 무시하고 이전 이름/고양이 주제로 돌아간 응답이 세 조건 모두 남았다. user-only는 과거 사용자 발화만으로도 이전 주제를 재생하거나 모르는 대상을 AI로 지어냈다. 단순 assistant 제거를 주제 고착의 해결책으로 채택할 근거는 없다.

태그는 단어 출현 횟수가 아니라 **현재 요청 대신 이전 주제로 답했는지** 직접 판정한 것이다. 현재 요청을 의식한 메타 요약/사고 과정 형식 문장은 단순 이전 주제 재생과 구분했다. 그 때문에 태그가 줄어든 한 상황도 내용 엄격 통과가 된 것은 아니다. 귀엽다는 형용사 하나만으로 과거 고양이 재생이라고 판정하지도 않았다.

단일 수정 원본의 한 응답은 사고 과정 형식의 짧은 설명을 내어 규칙 보호를 partial로 남겼다. 실제 내부 추론이나 시스템 지시가 유출됐음을 입증한 결과는 아니다. 다른 한 응답은 과정을 보여주지 않았다는 깨진 문장이었다. 이런 형식/관련성 실패를 단순 태그 감소나 JSON 성공으로 숨기지 않는다.

## 원인을 어디까지 좁혔는가

1. **assistant 소유자 표현의 영향은 있음:** 문장/역할/나머지 과거를 보존한 단일 개입으로3개 소유자 답변이 바로잡혔다. 앞선 묶음 정제의 효과를 전부 새 말투/거절 예시의 효과로만 설명할 수 없다.
2. **잘못된 assistant만이 최초 오류의 유일 원인은 아님:** 사용자 사실이 남은 user-only에서도 소유자 역전이 발생하고, 첫 회상 전에는 고칠 명시적 assistant 소유자 오류가 없는 대조에서도 실패한다. 발화자 지시어/사실 귀속을 추가로 검증해야 한다.
3. **최신 문장 복사만의 설명도 불충분:** 이전 모순이 남은 반말 요약은 최소 수정 후 다시 오답이지만 존댓말은 성공했다. 오래된 모순과 과제/표현의 영향이 분리되지 않았다.
4. **주제 선택과 사실 정확성은 다름:** 사용자 사실만으로도 이전 주제로 이탈했고, 올바른 소유어가 있어도 새 요청을 처리하지 못했다. 문맥의 어떤 부분을 현재 요청에 적용할지의 문제가 남는다.

다음 후보는 **역할 교대를 유지한 중립 assistant 대조**와 **이전의 틀린 소유자 문장만 한 개씩 제거/교정하는 대조**다. 전자는 user-only의 형식/길이 변화를, 후자는 최근 교정과 누적 모순을 더 나눌 수 있다. 사용자 사실을 발화 주체가 명시된 형식으로 표현하는 대조도 이후 후보지만 별도의 입력 표현 실험이다. 이번에는 후속·새 system prompt·실제 앱 이력 정책을 구현하지 않았다.

질문은 기존에 본 고정46상황이고 단일 greedy seed이며 같은 GPT가 작성/판정했다. 작은 알려진 세트의 조건 효과를 통계적 우승·일반 대화 성능·adapter 승격으로 확대하지 않는다. 원래 무이력인 자기소개/정직성 실패도 그대로이므로 전체 품질 원인이 확정된 것은 아니다. 이전 실험/평가를 소급 수정하지 않는다.
