# 제작자 회상과 사용자 이름 구분 · 2026-11-16

후속 작업에서 새아라·아라의 제작자 혼동과 같은 앱을 다른 표현으로 묻는 경우를 PC에서 다시 검증했다. [후속 실험의 실제 발화와 판정](local-llm-app-title-binding-report.md)

“제가 만든 앱 이름은 별담이에요.” 다음에 “별담을 만든 사람은 누구인가요?”라고 물으면 클로이는 이제 **“그 앱은 직접 만드셨다고 말씀하셨어요.”**라고 답한다. 같은 대화에서 별담을 사용자 이름으로 되묻던 답도 고쳤다. PC의 기존 4B 모델로 전후 240개와 추가 진단 4개를 새로 생성했다.

## 어디를 고쳤나

직전 필터 수정으로 사용자 원문은 이미 모델 입력에 남아 있었다. 하지만 앱 이름의 끝이 ‘이야/이에요’이면 이름을 하나로 확정하기 어렵다. 기존의 이름 기반 회상으로는 사용자가 명시한 제작 관계까지 놓쳤고, 모델 원문은 개발자를 모른다고 했다.

이번에는 유효한 모델 발화가 나온 뒤 실행하는 `GroundedConversationPolicy.resolve`에 회상 처리를 추가했다.

- 질문에 나온 이름을 앞선 **사용자**의 단일 앱 진술과 대조한다. 이름의 끝을 임의로 확정하거나 새 이름을 기억에 저장하지 않고, “내가/제가 만든”이라고 직접 밝힌 경우 제작 관계를 보고한다.
- 사용자가 앱 이름만 알려 준 경우 그 진술이 증명하는 범위까지만 답한다. 이후 정정으로 보일 수 있는 발화, 같은 이름의 반려동물, 일치하지 않는 이름에는 새 확정 답변을 적용하지 않는다. 이때 모델 자체가 틀릴 수 있다.
- 사용자가 자신의 이름을 아직 알려 주지 않았다고 명시하면서 앱 이름과 혼동하는지 물으면 두 정보를 분리해 답한다. 반말과 존댓말을 각각 지원한다. 물건 소유 회상은 기존 처리로 검증했다.

모델 입력을 만드는 코드와 소비 시점의 답변 선택을 분리했다. 직전 106개 이력을 동일하게 넣었을 때 전후 모델 입력은 106/106 같았다. 다중 턴은 각 조건에서 실제로 전달한 답을 각자의 다음 턴에 넣었으므로 중간 발화가 달라지면 그 뒤의 입력도 달라진다.

## 같은 질문으로 새로 생성한 결과

숫자는 GPT가 평가한 최종 발화의 **통과 / 부분 / 실패**다. 연속 대화의 질문은 동일한 5개 대화 × 6턴이다.

| 집단 | 수정 전 | 수정 후 | 상승 / 하락 |
| --- | --- | --- | --- |
| 기존 54문항 | 33 / 14 / 7 | 33 / 14 / 7 | 0 / 0 |
| 이전 독립 20문항 | 6 / 9 / 5 | 6 / 9 / 5 | 0 / 0 |
| 연속 30턴 | 15 / 9 / 6 | **17 / 8 / 5** | 2 / 0 |
| 이전 오답 이력을 고정한 2문항 | 1 / 0 / 1 | **2 / 0 / 0** | 1 / 0 |
| 다른 이름·소유·정정 등을 포함한 추가 14문항 | 6 / 3 / 5 | **8 / 2 / 4** | 2 / 0 |

**6턴 전체가 통과한 대화는 0/5에서 1/5로 늘었다.** 별담 대화의 2턴은 제작자를 모른다는 답에서 통과로, 4턴은 “혹시 별담이 제 이름이신가요?”라는 되묻기에서 통과로 바뀌었다. 5턴에는 만든 앱과 소유한 수첩을 구분했고, 6턴에는 앱을 언급하지 않고 목·어깨를 쉬게 하는 방법 두 가지를 답했다.

독립 74문항과 추가 14문항에서 전후 모델 입력 토큰과 모델 원문은 각 쌍에서 동일했다. 연속 대화는 26/30턴에서 입력과 원문이 같았다. 이 대화 집단에서 모델 원문만 평가하면 13 / 10 / 7에서 13 / 9 / 8이었다. 수정 후의 앱 대화 4턴에서도 원문은 사용자 이름을 “제 이름”으로 바꿨다. 최종 통과 증가는 앱이 실제로 전달한 답변의 개선이다.

## 무엇이 여전히 틀리는가

- 사용자가 만든 앱은 **새아라**인데 **아라**의 제작자를 물으면 둘을 혼동했다. 두 이름이 달라 새 회상 처리는 적용되지 않았다. 실제 모델 입력을 확인하니 이전 입력 정책이 질문에 ‘앱’이 있다는 이유로 “앱 제작자는 사용자다”라는 힌트를 넣었다.
- 이 힌트 **한 줄만** 뺀 고정 입력으로 추가 실험을 했다. 아라 질문에서 원문이 “아라 앱은 사용자님께서 직접 만들어 주셨어요”에서 “새아라 앱은 사용자님께서 직접 만들어 주셨군요”로 바뀌었다. 잘못된 제작자 단정은 사라졌지만 여전히 다른 앱에 답했다. 반대로 실제 같은 앱인 **도담이**에서는 힌트를 빼니 원문이 “개발자는 앱 제작자이신 분일 거예요”로 후퇴했다. 최종 답변은 양쪽 모두 사용자 진술을 반영했다. 두 사례로 본 효과이며 다음 변경에서는 **질문 대상과 근거가 같은 앱인지** 먼저 확인할 필요가 있다.
- 새 대조 14문항 중 실패한 나머지 세 가지는 앱과 강아지의 동명이름에서 모순된 답, assistant만 언급한 앱을 AI 자신과 동일시한 답, “은결 개발한 게 누구였는지 기억하세요?”라는 다른 표현에서 사용자 제작 진술을 놓친 답이다. 제3자 제작과 사용자 정정은 새 확정 답변의 대상에서 제외됐고, 모델은 정정된 제작자를 동생이라고 답했다.

## 검증과 재현

- 직전 커밋 `7068619`와 이번 소스를 별도 JVM에서 실행했다. 기존 4B Q4_K_M의 SHA-256은 `00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4`다. 동일 WSL CUDA worker와 llama.cpp revision `aa75ff3239f9cc675b081697deda9e1b112345c6`, GPU 33/33층, temperature 0, seed 42, context 2048, 최대 생성 384토큰, 스레드 4개, thinking off를 사용했다. 기존 54문항은 이전 고정 system, 다른 집단은 해당 기준선의 persona를 사용해 집단 내에서 비교했다.
- 주 비교 208개, 고정 이력 4개, 새 대조 28개에 대해 모델 원문·최종 JSON 계약과 정상 종료 **240/240**, 차단·잘림 0이었다. 별도 힌트 진단도 **4/4**였다. 수정 전 기존 106개는 직전 수정 후 결과와 이력·실제 입력 토큰·원문·최종 발화가 전부 일치했다. JVM **137/137**, 테스트용 누락·seed 변조·다른 조건 이력 혼입을 검증기가 모두 거부했다.
- 내용·말투·정직성·역할·문맥·지시 처리 6개 기준으로 평가했다. 이전과 질문·원래 이력·발화가 완전히 같은 경우 판정 출처를 남겨 재사용했고, 새로 달라진 29개 문맥/발화 조합은 직접 읽어 판정했다. 별도 진단 4개는 본 표에 중복 합산하지 않았다. 조건을 아는 개발자 평가이며 사람 블라인드 평가나 다양한 seed에서의 성공률 측정은 아니다.
- 재학습 0회. 기존 2B 원본, 10-step adapter, 보존한 폰 79개 결과의 SHA-256이 이전 기록과 일치했다. 4B에는 adapter를 적용하지 않았다. ADB 연결 목록에는 S20+만 있었고, 이번 수정의 S26 Ultra 설치·기기 추론·TTS 생성 및 재생은 미검증이다.
