# Sohee 1.7B 상황별 말투 비교 01

실제 대화에 사용할 표현을 고르기 위한 12문장 × 2조건 실험이다. 음성 인식이나 대화 엔진을 구현한 작업은 아니며, 작성한 한국어 문장을 Sohee가 읽는 표현력을 검증한다. APK와 기본 말투는 alpha3 그대로다.

## 비교 조건

일상·놀람과 호기심·공감·설명을 각각 3문장씩 준비했다. 문장과 지시 전문은 [재현 스크립트](../scripts/compare_situational_styles.py)와 결과 JSON에 있다. 통화 녹음이나 사용자 원문을 사용하지 않고 새로 작성한 예시다.

- **A:** 기존 말투인 `차분하고 다정하게, ` + 공통 호흡 지시.
- **B:** 해당 상황에 맞는 말투 지시 + 동일한 공통 호흡 지시.
- 공통 호흡 지시: `호흡은 필요한 의미 경계에서만 자연스럽게 사용하고, 매 문장 앞의 과장된 들숨은 반복하지 마세요.`

따라서 A는 호흡 지시를 추가한 대조군이며, 사용자가 앞서 생성한 기존 음성과 완전히 같은 지시가 아니다. 이번에는 **상황별 말투 지시 차이**를 비교한다. 호흡 절제 효과 자체를 분리 검증하는 실험은 아니다. 자연어 지시의 준수 여부도 청취해야 한다.

모델은 alpha3의 1.7B CustomVoice / Sohee / 한국어 / F16 + F32 CP-down이며, 모델 파일 크기와 SHA-256을 검사한다. 고정 런타임, CPU 4스레드, seed 42, temperature 0.9, top-k 50, top-p 1.0, repetition penalty 1.05, 최대 1024 토큰을 사용한다. 각 조건 1회이며 다중 seed 일관성은 아직 검증하지 않았다. PCM은 자르거나 음량을 정규화하지 않는다.

## 청취 순서

먼저 `daily_01`, `surprise_01`, `empathy_01`, `explanation_01`의 A/B를 듣는다. 각 파일 이름의 마지막 A/B가 조건이다. 이후 같은 상황의 02, 03에서도 선호가 유지되는지 확인한다.

발음·억양·리듬·감정 적절성, 단어 누락·추가, 첫 음절 보존, 문두 들숨 반복을 함께 평가한다. 작은 음량 차이도 선호에 영향을 줄 수 있다. 점수가 비어 있는 항목은 미평가이며 B가 더 좋다고 전제하지 않는다. 제공하는 CSV를 쓰거나 선호 파일과 이유만 전달해도 된다.

선호가 확인된 지시를 기존 alpha3의 말투 입력칸에 넣어 휴대전화에서 같은 문장으로 재생성한다. CPU 연산 차이로 같은 seed라도 호스트와 음성이 같다고 보장할 수 없다. 그 후 선택한 말투로 여러 문장을 이어 말하는 테스트를 진행한다. 현재 자료만으로 연속 발화의 자연스러움이나 통화 품질까지 검증했다고 판단하지 않는다.

## 실행

```sh
python3 scripts/compare_situational_styles.py \
  --binary /path/to/qwen3-tts-cli \
  --models models/chloe-sohee-1.7b-f16-stable \
  --output artifacts/situation-study-new
```

비어 있지 않은 출력 폴더는 거부한다. 결과의 `report.json`에는 문장·지시·모델 해시·측정값을, `listening.csv`에는 빈 청취 평가표를 기록한다. CLI 로그와 WAV는 artifacts에 남는다. PC 개발 환경의 속도는 Android 기기 성능을 뜻하지 않는다. `native_total_ms`는 모델 초기화·프로세스 시작·재생을 제외한 음성 코드 생성과 디코딩 시간이며, RTF는 그 시간 ÷ 오디오 길이다. 첫 출력 지연과 Android PSS·발열은 이번에 측정하지 않는다.

## 개발 환경의 측정 결과

24/24개 정상 생성, 비무음, 24kHz 모노 PCM16, 포화 샘플 0개, 토큰 상한 미도달을 확인했다. native 합성 시간 범위는 5.045–15.061초, RTF 범위는 1.558–1.971였다. 환경은 AMD EPYC 9V45 기반 Linux x86_64 가상 CPU, 추론 4스레드다. 측정 중 파일 업로드를 병행한 진단 결과이며 성능 최적화 벤치마크는 아니다.

[전체 조건 및 측정 JSON](validation/situation-study-01/results.json)에 결과를 기록했다. 청취 선호와 발음·감정·호흡 효과는 미평가다. 기존 PCM 검사 관련 단위 검증 3개와 12개 고유 입력·공통 호흡 지시 일치 검사를 통과했다. Android 코드 변경이 없어 새 APK를 빌드하지 않았다.

## 설명 청취 결과와 정정 당시의 판정

설명 평가 정정 당시의 판정은 **EXPLANATION_03_A를 설명 비교 기준으로 보존, 나머지 23개는 후보 제외**였다. 이후의 놀람 개별 평가는 아래에 반영했으며 해당 파일의 일괄 제외 판정을 대체한다. DAILY_03_A, EMPATHY_01_A, EXPLANATION_02_A도 마지막 메시지에서 명시적으로 폐기되었다. 점수가 없는 파일을 미평가로 두지 않고, 미언급 파일은 불량이라는 사용자 설명을 반영했다. 지적된 B 파일은 실패 원인 기록으로만 사용한다. 이 판정은 음성 선택 결과이며 Drive/로컬 파일을 물리적으로 삭제한 기록은 아니다.

설명은 감정·강조를 절제하고 중간 구절을 부드럽게 이어야 한다. 문장 종결을 불필요하게 올리지 않으며, 돼요의 0.1~0.2초 수준의 미세한 여운과 알 수 있어요의 과장된 늘임을 구별한다. 시간 값은 사용자 관찰·희망이며 기계 측정값이나 지시 준수 보장이 아니다. 첫 발화의 생성 시간은이 소시간은처럼 들린다는 발음 오류도 재검증한다.

[청취 판정](validation/situation-study-01/listening-feedback.json)과 [설명 재검증 계획](validation/situation-study-01/explanation-followup-plan.json)을 기록했다. 후속 음성은 아직 생성하지 않았고 앱 기본값도 바꾸지 않았다. 일상·공감에는 채택된 기준 음성이 아직 없다.

## 추가 놀람 청취 평가

사용자가 후속으로 평가한 놀람 파일은 이전의 미언급 일괄 제외보다 최신 판정을 우선한다. 이 평가는 사용자 청취 결과이며 에이전트의 직접 청취·정밀 F0 측정이 아니다.

| 파일 | 판정과 개선 목표 |
| --- | --- |
| surprise_01_A | 오~에 해당하는 감탄 표현을 맞장구 후보로 참고. 후속 질문은 딱딱해서 개선 필요 |
| surprise_01_B | 진짜??의 궁금함을 참고. 그래서 어떻게 됐어는 A/B 모두 조금 빠르고 궁금해서 재촉하는 표현 필요 |
| surprise_02_A | 와와 끝냈어의 감탄을 보존하고 빠른데까지 과하지 않은 감탄·상승·여운을 지속 |
| surprise_02_B | 폐기 |
| surprise_03_A | 전반적으로 좋은 기준. 잠깐에 집중·놀람·감탄과 하강 후 상승을 담고 후속 질문을 소폭 빠르게 |
| surprise_03_B | 낮고 차분한 별도 감정 변형으로 보존. 잠깐 뒤 차분한 끊음도 허용 |

설명은 불필요한 상승과 과한 감정을 줄이는 반면, 놀람은 감탄과 질문의 궁금함을 끝까지 유지한다. 두 상황에 같은 종결 규칙을 적용하지 않는다. 감탄사·질문 템포·문장 끝의 감정 지속을 나누어 평가한다. 보존한 구간을 편집·접합한 음성을 생성한 것은 아니다.

[놀람 후속 계획](validation/situation-study-01/surprise-followup-plan.json)에 지시 후보와 판정 기준을 준비했다. 원문의 문장부호를 먼저 유지하고 지시만 비교하며, 반복 물음표나 감탄사 철자 변경은 별도 실험으로 분리한다. 지시가 특정 음높이 곡선이나 감정을 보장하지 않으므로 재청취가 필요하다. 현재 앱은 사용자 발화 중 동시에 맞장구를 넣는 동작을 지원하지 않는다. 후속 WAV와 APK는 새로 만들지 않았다.
