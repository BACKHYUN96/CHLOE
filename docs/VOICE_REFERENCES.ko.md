# 클로이 말투 기준 표본 적용

마지막 사용자 청취 피드백을 기준으로 표본을 앱의 `voice-reference-catalog.json`에 고정한다. 이전 일괄 폐기/부분 선호보다 이후 파일별 재평가를 우선한다. 원본 측정 보고서의 당시 `pending` 기록은 과거 생성 시점의 기록이므로 덮어쓰지 않는다. 이 카탈로그가 최신 채택 상태다.

## 앱에서 사용하는 표본

| 원본 | 용도 | 마지막 평가와 유의점 |
| --- | --- | --- |
| surprise_01_A | 묵묵히 들어주는 친구 | REF 재평가 4.5/5 합격. 낮고 편안한 공감형으로 보존 |
| surprise_01_B | 낮은 시작의 공감 변형 | 4.5/5, 합격 근접. 첫 오가 과하게 눌린 점을 명시 |
| surprise_01_C | 차분한 공감과 궁금함 | 오·진짜·차분한 후속 질문 모두 합격. 끝을 일괄 상승시키지 않음 |
| surprise_02_A | 밝은 감탄 | REF 재평가 4.5/5 합격. 원본의 감탄을 기준으로 삼음 |
| explanation_03_A | 편안한 설명 | 전반적으로 괜찮고 B보다 우수. 끝의 웃는 여운은 아직 추가 목표 |

각 표본의 **원본 텍스트·실제로 사용한 말투 지시·원본 WAV SHA-256·출처**를 보관한다. REF는 원본의 복사본이므로 중복 표본으로 세지 않는다. 화면에서 `말투만 적용`은 현재 입력을 유지하고 지시를 적용한다. `예문과 말투 적용`은 검증에 쓰인 원문도 함께 넣는다. 직접 지시를 편집하면 표본 선택 표시를 해제한다. 결과 JSON에 선택한 표본과 `instruction_only`, `reference_pcm_used=false`를 남긴다. 0.6B는 자연어 지시를 지원하지 않아 표본 선택을 제공하지 않는다.

같은 지시를 공유하는 A 표본들도 서로 다른 맥락과 생성 결과다. 따라서 다른 문장에서 원본의 감정·억양이 그대로 재현된다고 보장하지 않는다. 현재 CustomVoice에 WAV를 참조 입력으로 전달하거나 가중치를 학습시키는 기능이 아니다. 매번 고정된 스타일 하나를 모든 상황에 강제하지 않고 사용자가 용도에 맞게 선택한다.

## 개선 기준으로만 보존하는 긍정 구간

- explanation_03_C: 전반적 선호. 시간이에요 → 오디오 길이와 비교하면 사이 새 들숨 없이 이어지는 개선 필요.
- surprise_02_C: 전반적 개선. 빠른데의 마지막 단어만 상승하도록 보완 필요.
- surprise_03_A: 후속 질문 선호. 잠깐의 집중·놀람·감탄과 질문 템포 보완 필요.
- surprise_03_B: 차분한 잠깐의 쉼을 별도 변형으로 보존.
- surprise_03_D: 03 C/D 중 가장 좋은 후보. 차가움을 줄이도록 잠깐 → 잠깐만…으로 변경하는 목표. 바뀐 대사를 합격으로 간주하지 않음.

이 다섯 개는 카탈로그에 보관하되 합격 프리셋 버튼에 노출하지 않는다. 폐기된 일상·공감·설명 A, surprise_02_B 등은 선택 대상에서 제외한다. explanation_01_B/02_B와 후속 C의 수정 요구도 합격으로 승격하지 않는다. surprise_03_C는 전반적 어색함 때문에 선택 대상에서 제외한다. 아직 평가하지 않은 수정 비교 03 음성도 채택하지 않는다.

## 공통 표현 정책

`↗↘`는 억양 방향, `? ?? ??? ! !! !!! ~ ~~ ~~~`는 말투·감정 의도다. 이 표기를 실제 합성 텍스트에 기계적으로 덧붙이지 않는다. 웃음은 상황에 따라 미소가 담긴 발성 또는 실제 짧은 웃음을 구분하고, 모든 발화에 삽입하지 않는다. 매 발화 앞의 들숨을 강제하지 않으며 연속 설명의 불필요한 호흡·쉼을 줄이는 것이 목표다. 길이 0.1~0.2초나 특정 F0 곡선을 제어하는 구현은 없다.

원본 WAV를 앱에 넣거나 잘라서 맞장구로 재생하는 기능은 이번 범위가 아니다. 고정 맞장구 음원은 향후 원본 접근·구간 청취·컷 지점 검증 후 별도로 준비한다. 새 음성도 이번 작업에서 생성하지 않는다.

## 성능 기준과 확인

alpha6은 CPU alpha4에서 분기했다. Vulkan·하이브리드 코드와 120초 제한은 포함하지 않는다. 8스레드의 이전 지연을 피하도록 자동 비교는 2·4·6만 사용한다. CPU 4스레드를 권장하며 모델·정밀도·native 합성 동작을 바꾸지 않았다. alpha5보다 높은 versionCode와 Performance의 동일 패키지·서명을 사용하므로 GPU 실험판 위에 업데이트할 수 있다.

단위 검증은 원본 지시·텍스트·해시 일치, 폐기 표본 차단 및 선택 목록을 확인한다. 휴대전화에서 버튼 동작·원본 대비 발음·억양 재현은 별도 확인이 필요하다. PR에는 실제 빌드·검증 결과를 기록한다.
