# Sohee 1.7B 호흡 표현 비교 01

호흡을 매번 강제하지 않으면서 자연스러운 발음을 유지할 수 있는지 평가하기 위해 **3가지 입력 × 5가지 지시 = 15개 WAV**를 생성했다. 전부 생성 및 PCM 검사를 통과했지만, **청취 평가와 호흡 절제 효과는 아직 미확인**이다. 이번 작업은 비교 자료와 재현 도구를 추가한다. APK, 모델 가중치, 앱 기본 말투는 변경하지 않는다.

## 조건

- 모델: `Qwen3-TTS-12Hz-1.7B-CustomVoice`, Sohee, 한국어
- 변환: 기존 alpha3와 동일한 F16 + F32 CP-down 모델 팩, 파일 크기와 SHA-256 확인
- 런타임: `qwen3-tts.cpp`의 고정 커밋 `4562731dc612cb87b4cd1eedac275a17d1078773`
- 환경: Linux x86_64 개발 환경, AMD EPYC 9V45 기반 가상 CPU, CPU 4스레드
- seed 42, temperature 0.9, top-k 50, top-p 1.0, repetition penalty 1.05, 최대 1024 토큰
- 조건마다 프로세스를 새로 실행하고 1회 생성. 24kHz / 모노 / PCM16, 원본 PCM 유지
- 자르기, 음량 정규화, 호흡 음원 삽입 없음

입력 `01`은 사용자가 제공한 다문장 입력을 줄바꿈·문장부호까지 유지했다. 이 원문과 생성 WAV, 원본 로그는 공개 저장소에 넣지 않는다. `02`는 짧은 대화 턴용 문장, `03`은 공감 반응용 문장이다. **실제 대화, 청크 간 연속성, 속도를 지시한 빠른 템포 실험은 아직 아니다.**

| 지시 | 조건 |
| --- | --- |
| A | 지시 없음 |
| B | 기존 지시 `차분하고 다정하게, ` 유지 |
| C | B에 한국어로 과장된 선행 들숨 반복을 줄이고 필요한 호흡만 사용하도록 요청 |
| D | 영어로 차분하고 다정한 말투만 요청한 대조군 |
| E | D에 영어로 호흡 절제 요청 추가 |

같은 입력의 **B/C**, **D/E**를 각각 비교한다. D/E의 발화 언어도 한국어다. 지시 전문은 [실험 스크립트](../scripts/compare_breath_styles.py)에 있으며, 개인 Drive의 실험 조건 파일에는 실제 입력·지시를 보관한다. 자연어 지시는 강제 제어가 아니므로 준수 여부를 청취해야 한다.

## 생성 결과

15개 모두 정상 종료, 비무음, 24kHz 모노 PCM16, 토큰 상한 미도달, 포화 샘플 0개였다. 단어 누락·추가, 문두 발음 손상, 호흡과 잡음의 구분, 억양·감정의 적절성은 자동 검사로 판정하지 않았다.

| --- | ---: | ---: | ---: |
| 01_A | 11.60 | 17.435 | 1.503 |
| 01_B | 11.36 | 17.345 | 1.527 |
| 01_C | 11.20 | 17.837 | 1.593 |
| 01_D | 11.84 | 17.889 | 1.511 |

| 02_C | 3.68 | 6.271 | 1.704 |
| 02_D | 3.36 | 5.241 | 1.560 |
| 02_E | 3.76 | 6.552 | 1.743 |

`native 합성`은 CLI가 보고한 `Total`(음성 코드 생성 + vocoder decode)이다. 모델 초기화, 프로세스 시작, WAV 저장·재생 지연은 포함하지 않는다. RTF는 이 시간 ÷ 오디오 길이다. CLI의 `Code generation`과 `Total`을 구분해 [측정 JSON](validation/breath-study-01/public-summary.json)에 기록했다. 원본 CLI의 peak RSS 표시 범위는 4.37–5.15 GB이며 Android PSS와는 측정 방식이 다르다. 첫 재생 출력은 측정하지 않았다.

이 값은 **개발용 Linux CPU에서 얻은 결과**다. 휴대전화 측정이나 사용자 PC 서버의 예상 성능으로 해석하지 않는다. 음성이 짧아졌거나 RMS가 낮아진 것만으로 호흡이 줄었다고 판단하지 않는다. 현재 seed는 하나이며 여러 seed에서의 일관성도 미검증이다. 휴대전화와 호스트의 연산 차이로 같은 seed라도 출력이 다를 수 있다.

## 청취와 후속 결정

1. 우선 `01_B.wav`와 `01_C.wav`를 비교한다. 필요하면 D/E와 지시 없는 A도 듣는다.
2. 문두 들숨 반복, 첫 자음·음절 보존, 단어 누락·추가, 발음·억양·리듬·감정 표현을 함께 확인한다. 음량 차이가 선호에 영향을 줄 수 있으므로 유의한다.
3. 짧은 턴 `02`, 공감 반응 `03`에서도 같은 지시가 자연스러운지 확인한다. 선호와 이유만 간단히 기록해도 되고, 제공한 빈 평가 CSV를 사용할 수도 있다.
4. 개선 후보가 확인되면 기존 alpha3의 말투 입력칸에 해당 지시를 넣어 휴대전화에서 재생성하고 WAV/JSON을 내보낸다. 검증 후 기본값 적용 여부를 결정한다.

개인 Drive 패키지에는 15개 개별 WAV, 청취 안내, 빈 평가 CSV, 원문을 포함한 실험 조건 JSON과 묶음 ZIP을 제공한다. 공개 저장소에는 개인 원문·오디오가 없는 측정 요약만 보관한다. 호흡 자동 분류·제거, 맥락에 따른 호흡 선택, PC 서버와 대화 API는 이번에 구현하지 않았다.

## 재현

모델과 CLI를 먼저 준비한다. 기본 실행은 스크립트에 공개된 예시 입력을 사용하므로 사용자 원문을 쓴 이번 `01`과 입력이 다르다.

```sh
python3 scripts/compare_breath_styles.py \
  --binary /path/to/qwen3-tts-cli \
  --models models/chloe-sohee-1.7b-f16-stable \
  --output artifacts/breath-study-new
```

개인 평가 입력을 유지하려면 `--evaluation-json /path/to/chloe-evaluation.json`을 추가한다. `model_variant=1.7b`, `input`, `instruction` 필드를 사용한다. 스크립트는 모델 팩 해시를 검사하고 비어 있지 않은 출력 폴더를 거부한다. 결과 폴더의 `private-report.json`과 CLI 로그에는 입력이 포함되므로 공개하지 않는다. 공개용 요약은 `public-summary.json`이다.

스크립트의 개인정보 제외·PCM 측정·잘못된 오디오 형식 거부 검증 3개를 실행해 통과했다. Android 앱 코드 변경이 없어 APK를 새로 빌드하지 않았다.

```sh
python3 -m unittest discover -s scripts -p 'test_compare_breath_styles.py'
```
