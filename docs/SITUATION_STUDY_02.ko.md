# 설명·놀람 수정 비교 02

사용자 피드백을 반영해 설명 3개, 놀람 3개와 낮고 차분한 놀람 변형 1개를 새로 생성했다. **신규 7개 생성과 기본 PCM 검사는 통과했으며, 개선 여부는 청취 대기 중**이다. APK와 기본 말투는 alpha3 그대로다. 이어 말하기와 실시간 맞장구는 이번 검증에 포함하지 않는다.

## 비교 조건

01 실험의 원문·문장부호·모델 팩·CPU 4스레드·seed 42·샘플링·공통 호흡 지시는 유지하고 말투 지시만 바꿨다. `↗↘`는 억양 방향, 반복된 `?`, `!`, `~`는 말투와 감정의 사용자 표현으로 해석했다. 이 표기를 원문에 추가하지 않았다. 실제 사용한 문장과 지시 전문은 [결과 JSON](validation/situation-study-02/report.json)에 고정했다.

설명 02의 미세한 여운 지시가 240자 제한에 들어가도록 설명 공통 지시의 중복 표현을 간결하게 줄였다. 마지막 음절의 0.1~0.2초 길이와 억양 곡선을 정확히 제어하거나 측정했다는 의미는 아니다. 모델 지시의 준수는 청취로 확인해야 한다.

| 신규 파일 | 청취 기준 |
| --- | --- |
| explanation_01_C | 열고 뒤 과한 쉼, 설정을의 불필요한 상승을 줄이고 부드럽게 연결 |
| explanation_02_C | 보세요의 안정된 종결과 돼요만의 짧고 은은한 여운 |
| explanation_03_C | 생성 시간은의 첫 발음 보존, 감정과 어미 늘임 절제 |
| surprise_01_C | 부드러운 감탄사, 진짜의 궁금함, 빨리 답을 듣고 싶은 후속 질문 |
| surprise_02_C | 좋은 첫 감탄을 유지하며 빠른데까지 과하지 않은 감탄 지속 |
| surprise_03_C | 잠깐의 집중·놀람·감탄과 하강 후 상승, 조금 빠른 후속 질문 |
| surprise_03_D | 낮고 차분한 별도 표현, 잠깐 뒤 짧은 쉼 허용 |

## 참고 음성

01에서 참고 대상으로 보존한 `explanation_03_A`, `surprise_01_A/B`, `surprise_02_A`, `surprise_03_A/B` 6개를 **재생성 없이 원본 그대로 복사**했다. 이전 결과의 SHA-256과 일치를 확인했고, `REF_` 접두어로 신규 후보와 구분했다. [참고 원본 목록](validation/situation-study-02/references.json)에 출처와 해시를 기록했다. 부분 선호 음성을 전체 채택 또는 기본값 승인으로 취급하지 않는다.

설명 03 A/C 및 각 놀람의 기존 참고/신규 후보는 같은 문장 비교가 가능하다. 설명 01·02의 신규 C와 설명 03의 참고 A는 문장이 다르므로 설명의 담담한 말투만 참고한다. 폐기된 설명 파일과 surprise_02_B는 재업로드하지 않았다.

Drive 패키지에는 WAV 13개(신규 7개·참고 6개), 청취 안내 TXT, 빈 평가 CSV, 결과와 참고 출처 JSON, 전체 ZIP을 넣는다. ZIP의 내부 파일 17개를 CRC 검사했다. 점수가 비어 있으면 미평가다. 신규 파일의 개선을 전제하지 않고 발음·리듬·감정·원치 않는 호흡·단어 누락/추가도 함께 듣는다.

## 실제 검증

- 모델 팩 크기/SHA-256 검사 후 7/7 정상 종료, 비무음, 24kHz 모노 PCM16, 포화 샘플 0개, 토큰 상한 미도달 확인.
- 신규 native 합성 시간 6.419–12.673초, RTF 1.811–2.170. Linux x86_64 개발용 AMD EPYC 9V45 가상 CPU, 추론 4스레드 결과이며 Android 성능이 아니다. 참고 파일 업로드를 병행한 진단값이다.
- native 시간은 코드 생성+디코딩이며 모델 초기화·프로세스 시작·WAV 저장·재생 지연을 제외한다. 첫 출력·Android PSS·발열은 미측정.
- 원문 일치, 6개 입력·7개 지시 구성, 240자 제한과 동일 호흡 지시를 검사했다. 기존 PCM/공개 요약 단위 검증 3개도 통과했다.
- PCM 자르기·늘이기·접합·피치 변조·음량 정규화를 적용하지 않았다. 서로 음량이 다를 수 있으며 청취 선호에 영향을 줄 수 있다.
- 한 seed, 조건마다 한 번 생성했다. 다중 seed 일관성과 휴대전화 재현, 사용자 청취 평가는 아직이다. Android 코드 변경이 없어 새 APK를 빌드하지 않았다.

## 재생성

```sh
python3 scripts/compare_situational_styles.py --followup \
  --binary /path/to/qwen3-tts-cli \
  --models models/chloe-sohee-1.7b-f16-stable \
  --output artifacts/situation-study-02-new
```

이 명령은 7개 신규 후보와 결과 JSON/빈 CSV를 생성한다. 참고 복사·ZIP 포장은 별도다. 지시는 docs/validation/situation-study-01의 설명·놀람 후속 계획에서 읽는다. 계획을 수정하면 조건이 바뀌므로 이번 결과의 정확한 조건은 보관한 결과 JSON을 기준으로 한다. 비어 있지 않은 출력 폴더는 거부한다.

선호하는 구간과 수정할 구간을 받은 뒤 후보를 고르고, 그다음 여러 문장을 이어 말하는 검증을 진행한다. 동일 seed라도 호스트와 폰의 연산 차이로 음성이 같다고 보장하지 않는다.
